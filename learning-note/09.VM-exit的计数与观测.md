# 卷九：VM exit 的计数与观测

<!-- learning-note/09.VM-exit的计数与观测.md -->

本卷讲 `--exit-stats`：VM 停下之后，按 exit 类型、按设备报告 guest 一共让 VMM 处理了多少次 exit，并把 KVM 自己的计数器放在旁边对照。对应里程碑 `exit-stats`，代码在 `src/vm.c`（计数）、`src/exit_stats.c`（报告）、`src/kvm_stats.c`（KVM 二进制统计的解析）、`src/main.c`（选项和时机）。

## 1. 要解决的问题

路线图后半段几乎每个里程碑都是“同一件事换一种做法，看它便宜了多少”：e1000 对 virtio-net，`KVM_EXIT_MMIO` 对 ioeventfd，用户态后端对 vhost。比较的第一个量就是 exit：一次 I/O 让 guest 停下来几次，停下来之后是在内核里就地处理，还是一路回到 VMM 的用户态。

光有 VMM 自己的计数不够。VMM 只看得到回到用户态的那部分 exit，内核就地处理掉的（NPT 缺页、LAPIC 定时器、内核里模拟的 PIC/PIT 端口、带内核 LAPIC 时的 HLT）对它是不可见的。所以报告分两半，用户态一半由 VMM 计数，内核一半读 KVM 的二进制统计接口 `KVM_GET_STATS_FD`，两半并排才能回答“这次 exit 付出了哪一段开销”。

## 2. 数据从哪里来

```text
 guest 执行 out/in/hlt/访问 MMIO
        │  VM exit（#VMEXIT）
        ▼
 KVM: svm_handle_exit ──► io_interception: ++stat.io_exits ─┐
        │                  __kvm_emulate_halt: ++stat.halt_exits
        │                  vcpu_enter_guest: ++stat.exits    │  KVM_GET_STATS_FD
        │                                                    │  （报告第 3、4 段）
        ├─ 内核能处理（PIC/PIT 端口、内核 LAPIC 下的 HLT、缺页）─► 直接回到 guest
        │
        ▼ 需要用户态
 KVM_RUN 返回，kvm_run->exit_reason
        ▼
 vcpu_handle_exit: vcpu->exits[exit_reason]++        （报告第 1 段，按 vCPU）
        ▼ 持 io_lock
 io_bus_dispatch_pio/mmio: vm->pio_stats[设备下标]    （报告第 2 段，按设备、按方向）
                           或 vm->pio_unhandled / mmio_unhandled
```

## 3. 用户态计数的设计

### 3.1 按 exit_reason：每个 vCPU 一张表

`struct vmm_vcpu` 里的 `uint64_t exits[VMM_EXIT_REASON_SLOTS]`，下标直接是 `KVM_EXIT_*` 的值。`<linux/kvm.h>` 里的 exit reason 目前不到 50 个，表有 64 格，超出范围的值都记进最后一格，报告里叫 `out-of-range`。下标来自内核写的 `kvm_run`，按“不可信输入”处理，所以要钳位，不能直接拿来索引。

计数只有本 vCPU 线程写，报告只在全部 vCPU 线程 join 之后读，`pthread_join` 本身就是同步点，不需要锁或原子操作。

`KVM_RUN` 被信号打断返回 `EINTR` 时不计数：这时 `exit_reason` 不是这一次的值（`immediate_exit` 路径下 KVM 不改写它），`vcpu_run_loop()` 在交给 `vcpu_handle_exit()` 之前就把它挡掉了。

### 3.2 按设备：和设备表平行的数组

`vm->pio_stats[i]` 对应 `vm->pio_devs[i]`，MMIO 同理，另有 `pio_unhandled`、`mmio_unhandled` 两格收容落在未注册地址上的 exit。计数和设备表分开放，是因为设备表注册完之后只读，`vmm_lookup_pio()` 返回 `const` 指针、查找不加锁；计数在分发路径上更新，那里本来就持着 `io_lock`。

计的是 exit 次数，不是访问次数。`rep outsb` 一次 exit 带 `count` 个字节，设备回调被调用 `count` 次，统计只加一。要回答的问题是“exit 的开销花在了哪个设备上”，开销按 exit 付。

### 3.3 一直在计，选项只决定输出

计数代码没有开关。持锁路径上的一次自增，和一次 exit 本身（几微秒的世界切换加一次用户态往返）相比可以忽略；加开关反而要在每个计数点多一个分支，还会让“开和关的行为一致”多出一个需要证明的地方。`--exit-stats` 只决定 VM 停下后是否输出报告、输出到哪里。

统计文件在启动时就打开，路径写错会在 guest 运行之前报错退出，不会跑完一整次才发现结果无处可写。VM 出错停下时也照样输出：exit 落在哪里正是排错的线索。

## 4. KVM 的二进制统计

### 4.1 文件格式

`ioctl(fd, KVM_GET_STATS_FD)` 对 vm fd 或 vcpu fd 都能调，返回一个只读 fd，格式在 `Documentation/virt/kvm/api.rst` 4.133 节：

```text
offset 0        struct kvm_stats_header { flags, name_size, num_desc,
                                          id_offset, desc_offset, data_offset }
id_offset       id 字符串（name_size 字节），如 "kvm-12345/vcpu-0"
desc_offset     num_desc 个 { struct kvm_stats_desc（16 字节）, name[name_size] }
data_offset     数据块；第 i 项的值在 data_offset + desc[i].offset，desc[i].size 个 u64
```

`desc.flags` 的低 4 位是类型（CUMULATIVE、INSTANT、PEAK、LINEAR_HIST、LOG_HIST），4–7 位是单位，8–11 位是 exponent 的底。报告只取 `size == 1` 的单值项，直方图（halt-polling 时长分布之类）要按 bucket 解释才有意义，exit 计数用不上，解析时跳过并计数。

### 4.2 反直觉的地方：别按“紧挨着”去读

真实内核给出的文件恰好是 header、id、desc、data 依次紧挨着的，但 api.rst 明确写了“不保证相邻，也不保证按这个顺序”。按位置猜的实现在今天的内核上完全正常，换一个内核就读出错位的值，而且不会报错。`kvm_stats_read()` 一律用 header 里的 offset 加 `pread` 定位。

第二个坑是对齐。desc 的步长是 `16 + name_size`，内核的 `name_size` 是 48，步长 64 恰好对齐；但规范没有承诺 `name_size` 是 8 的倍数，直接把缓冲区里的指针强转成 `struct kvm_stats_desc *` 在步长不对齐时是未定义行为。实现先 `memcpy` 出定长部分再用。

第三个是防御损坏的文件：`name` 必须在 `name_size` 之内以 `'\0'` 结尾，`desc.offset` 是 u32，不设上限的话一个损坏的值能让解析器先 `malloc` 4 GiB 再发现文件没那么长，所以数据块限制在 1 MiB（x86 vCPU 的实际数据块不到 4 KiB）。

### 4.3 什么时候读

vcpu 的 ioctl 进入 `kvm_vcpu_ioctl()` 时先拿 `vcpu->mutex`（`virt/kvm/kvm_main.c`），而 `KVM_RUN` 期间这把锁一直被 vCPU 线程持有。别的线程在 guest 运行时去调 `KVM_GET_STATS_FD` 会卡到 vCPU 退出为止。报告在 `vm_run()` 返回（全部 vCPU 线程已 join）之后、`vm_destroy()` 关掉 fd 之前读，两个条件同时满足。

## 5. 实际观察到的数

### 5.1 裸 payload：每个数都能从源码数出来

`tools/payload/serial_stub.S` 打印 31 个字符的一行，每个字符先读 LSR 再写 THR（mini-vmm 的 LSR.THRE 恒为 1，不会多轮询），之后 SCR 写读各一次、MCR 写两次、MSR 读一次，最后写一次 dbg-port 再 `hlt`：

```text
$ ./build/vmm --mode long64 --exit-stats - build/serial64.bin
user-space exits by reason (KVM_RUN returned to the VMM)
  IO                                   68           68
  HLT                                   1            1
user-space exits by device (string I/O counts once per exit)
  dbg-port                   PIO               0            1
  serial8250                 PIO              33           34
KVM vCPU stats (KVM_GET_STATS_FD, ...)
  pf_taken                              4            4
  exits                                73           73
  io_exits                             68           68
  halt_exits                            1            1
```

serial 读 31+1+1=33，写 31+1+2=34，加 dbg-port 一次，IO 共 68。KVM 的 `io_exits` 也是 68：这个模式下没有创建内核 irqchip，所有端口都回到用户态。KVM 的 `exits` 比用户态的 69 多 4，恰好是 `pf_taken` 的 4 次：guest 第一次访问各个页（页表、GDT、代码）时的 NPT 缺页，由 KVM 建好映射后直接回到 guest，VMM 完全不知道。

### 5.2 Linux guest：内核吃掉的那部分

`--mode linux --smp 2` 启动到 shell 再 `poweroff -f`，一次典型的报告（数字每次略有不同）：

| 量 | 用户态 | KVM | 差值说明 |
|---|---|---|---|
| IO | 54849 | `io_exits` 55012 | 163 次落在内核模拟的端口上：mini-vmm 用 `KVM_CREATE_IRQCHIP`、`KVM_CREATE_PIT2` 把 PIC、PIT 放进了内核，`emulator_pio_in_out()` 经 `kvm_io_bus_read(KVM_PIO_BUS)` 就地处理 |
| HLT | 0 | `halt_exits` 465 | 有内核 LAPIC 时 `__kvm_emulate_halt()` 只把 vCPU 置为 HALTED，在内核里睡到下一个中断，不回用户态 |
| 总数 | 54849 | `exits` 66675 | 其余是外部中断（`irq_exits` 4209）、中断窗口（`irq_window_exits` 927）、缺页、指令模拟 |

按设备看，串口占了用户态 exit 的 98%（26787 读、27398 写）。同一次启动用 `--trace-pio` 加 `tools/pio_decode.py --summary` 按端口拆开，THR（0x3f8 写）26751 次、LSR（0x3fd 读）26006 次，几乎一比一：控制台输出是逐字节先查 LSR.THRE 再写 THR，每个字节两次 exit。这是后面 virtio-console 的对照基线。`unhandled PIO` 里最多的是 0xcf8 写、0xcfc/0xcfe 读，即 Linux 用 PCI 配置机制 #1 探测总线，`pci-bus` 里程碑实现它之后这部分 exit 会移到新设备的行上；其余是 0x2e/0x4e 这类 Super I/O 端口的盲探。

## 6. 为什么现有验证足够

- `tests/unit/kvm_stats_test.c` 用 memfd 造出规范允许、但真实内核不会给出的布局：块顺序倒置、块间留空、`name_size` 不是 8 的倍数，再加七种损坏文件。按位置猜 desc 块、按位置猜数据块、强转不对齐指针、不限制数据块长度这四种错误实现各自至少挂一条（强转不对齐由 UBSan 报出；不限长度的那种靠测试里把单次分配上限压到 64 MiB，让它从 INVAL 变成 NOMEM）。
- `tests/unit/io_bus_test.c` 的 `case_stats` 经 `vcpu_handle_exit()` 摆出一串 exit，逐项核对计数。按回调计数、不分方向、MMIO 未注册计进 PIO 那格、exit_reason 不钳位，这四种错误实现都会让它失败。
- `tests/e2e/exit-stats.sh` 在真 KVM 上跑两个裸 payload，报告里的每一个数都与上面从源码数出的值逐项相等，KVM 的 `io_exits` 与用户态 IO 相等、`exits` 不小于用户态总数；打开和关闭统计时 guest 的 stdout 逐字节相同；Linux guest 用内部一致性校验（各设备行的读写之和等于 IO、MMIO 两行）。旧版本的 VMM 不认识 `--exit-stats`，全部用例都失败。

## 7. 限制

- 没有按端口或 MMIO 偏移的细分。按设备已经能回答“哪个设备贵”，要看单个寄存器用 `--trace-pio`。
- 没有每次 exit 的耗时。时间开销要靠 host 侧的 `perf kvm stat` 或 `exit-cost` 里程碑在 guest 里测。
- KVM 统计只读一次，在 VM 停下之后。运行中的观察属于 `monitor` 里程碑。
