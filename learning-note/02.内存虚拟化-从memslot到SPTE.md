# 卷二：内存虚拟化 —— 从 memslot 到 SPTE

> 承接卷一。本卷回答一个卷一没有回答的问题：**Guest 执行一条普通的 `mov` 访问某个物理地址时，硬件凭什么知道这块地址是 RAM 还是设备寄存器？**
>
> 答案不在任何一张设备表里，而在 NPT 页表项的保留位上。
>
> 源码基于 Linux **v5.15**，硬件行为依据 AMD64 APM Vol.2 §15.25（Nested Paging）。

---

## 1. 三层地址与两套页表

### 1.1 为什么必须有 GPA 这一层

Guest 内核在启动时会做一件事：探测物理内存布局，建立 `struct page` 数组，初始化伙伴系统。此后它分配的每一个页帧、写入的每一个页表项，用的都是它认为的"物理地址"。

如果让 Guest 直接使用 HPA，会立刻遇到三个问题：Guest 必须知道自己被分配了哪些不连续的物理页（破坏了"我独占整台机器"的抽象）；Host 无法在 Guest 运行时迁移物理页（KSM 合并、THP 折叠、内存压缩全部失效）；两个 Guest 无法被隔离（一个 Guest 写错地址就能踩到另一个）。

所以中间必须插一层 **GPA（Guest Physical Address）**：Guest 眼中连续的、从 0 开始的物理地址空间，实际上是 Host 用某种映射拼出来的。

```
      Guest 用户态指针                Guest 内核指针
            │                              │
            └──────────┬───────────────────┘
                       │ GVA
                       │
        ┌──────────────▼───────────────┐
        │  Guest 页表（Guest 自己维护） │  根：Guest CR3（内容是 GPA）
        │  Guest 有完全的读写权         │
        └──────────────┬───────────────┘
                       │ GPA
                       │
        ┌──────────────▼───────────────┐
        │  NPT（Host/KVM 维护）         │  根：VMCB.control.nested_cr3
        │  Guest 完全不可见、不可访问    │       （内容是 HPA）
        └──────────────┬───────────────┘
                       │ HPA
                       ▼
                  物理内存条
```

关键性质：**Guest 可以任意修改自己的页表而不产生任何陷出**。`CR3` 的读写不被拦截，`invlpg` 也不拦。Guest 内核的缺页处理、进程切换、`fork` 时的页表复制，全部在 Guest 模式里全速完成。这是硬件二级页表相对影子页表的根本优势。

### 1.2 影子页表为什么被淘汰

在 NPT/EPT 出现之前（AMD 是 2008 年的 Barcelona，Intel 是 2009 年的 Nehalem），只有一套硬件页表可用，Hypervisor 只能维护一张合成的 **影子页表（Shadow Page Table）**，直接把 GVA 映射到 HPA，让 `CR3` 指向它。

代价是必须让 Guest 对自己页表的每一次修改都被感知到，做法是**把 Guest 的页表页设为只读**：Guest 一写页表就触发 `#PF`，Hypervisor 拦下来，解析它想写什么，同步更新影子页表。

这条路径的开销是灾难性的：一次 `fork()` 会复制整棵页表，触发成百上千次写保护缺页；每次进程切换换 `CR3`，Hypervisor 要么重建整棵影子页表，要么维护一个影子页表缓存（还得处理缓存失效）。工程复杂度同样惊人——KVM 里 `arch/x86/kvm/mmu/paging_tmpl.h` 那套用 `#include` 两次实现 32 位/64 位两个版本的模板代码，就是影子页表的遗产。

5.15 里影子 MMU 仍然存在（用于不支持 NPT 的老 CPU、以及某些嵌套虚拟化场景），但默认路径是 TDP MMU。

### 1.3 二维漫游的访存代价

开启 NPT 后，一次 GVA → HPA 翻译由硬件独立完成，但硬件做的工作量急剧上升。

关键在于：**Guest 页表本身存放在 Guest 物理内存里，所以访问 Guest 页表的每一级，都需要先做一次 GPA → HPA 翻译。**

四级页表下（PML4 → PDP → PD → PT），推导如下：

```
   记 Guest 页表级数 = 4，NPT 级数 = 4

   翻译 Guest CR3 (GPA) → HPA            需要 4 次 NPT 访存
   读 Guest PML4E                        1 次
   翻译 PML4E 中的 GPA → HPA             4 次
   读 Guest PDPE                         1 次
   翻译 PDPE 中的 GPA → HPA              4 次
   读 Guest PDE                          1 次
   翻译 PDE 中的 GPA → HPA               4 次
   读 Guest PTE                          1 次
   翻译 PTE 中的目标 GPA → HPA           4 次
   ─────────────────────────────────────────────
   合计                                  24 次物理内存访问
```

也可以记成 (4+1) × (4+1) − 1 = 24。裸机上同样的翻译只需 4 次访存。

这个数字解释了虚拟化环境下的几个经验规律：

- **大页在虚拟化下比裸机更重要。** Guest 侧用 2 MB 页可以把 Guest 页表级数从 4 降到 3，NPT 侧用 2 MB 页可以把 NPT 级数降到 3，两边一起降就是 (3+1)×(3+1)−1 = 15 次。KVM 默认允许 NPT 使用 1 GB 页（`kvm_configure_mmu(npt_enabled, get_max_npt_level(), get_max_npt_level(), PG_LEVEL_1G)`）。
- **TLB 命中率的价值被放大。** TLB 缓存的是最终的 GVA → HPA 结果，命中时 24 次访存全部省掉。这也是卷一讲的 ASID 存在的意义——避免因世界切换而丢失这些昂贵的翻译结果。
- **页表遍历缓存（Page-Walk Cache）在虚拟化下承担更多。** 现代 CPU 会缓存中间级页表项，二维漫游时这些缓存的收益是乘法级的。

Intel 的 EPT 在这一点上完全相同，24 次是两家共有的最坏情况。

### 1.4 NPT 与 EPT 的格式差异

这是 AMD 和 Intel 在内存虚拟化上最实质的分歧。

**AMD NPT 直接复用标准 x86-64 页表格式**：bit 0 = Present、bit 1 = R/W、bit 2 = U/S、bit 7 = PS(大页)、bit 63 = NX，物理地址在 bit 51:12。这意味着 NPT 页表项和普通页表项可以用同一套宏来构造。

**Intel EPT 使用独立格式**：bit 0 = Read、bit 1 = Write、bit 2 = Execute（三个权限位独立），bit 5:3 = 内存类型（EPT memory type，相当于把 PAT 的功能内嵌），没有 U/S 位（EPT 不区分特权级，特权检查由 Guest 页表完成）。

这个差异在 KVM 代码里的体现是：**SPTE 的每一个权限位都不是常量，而是全局变量**：

```c
/* arch/x86/kvm/mmu/spte.c */
u64 __read_mostly shadow_present_mask;
u64 __read_mostly shadow_user_mask;
u64 __read_mostly shadow_x_mask;      /* EPT 下是 bit 2，NPT 下是 0（x86 无 X 位） */
u64 __read_mostly shadow_nx_mask;     /* NPT 下是 bit 63，EPT 下是 0 */
u64 __read_mostly shadow_mmio_value;
u64 __read_mostly shadow_mmio_mask;
u64 __read_mostly shadow_me_mask;     /* AMD SME 内存加密位 */
```

`make_spte()` 里那一堆 `spte |= shadow_x_mask` 之所以看起来抽象，就是因为它必须同时生成两种硬件格式的页表项。VMX 侧在 `vmx_setup_me_spte_mask`/`kvm_mmu_set_ept_masks()` 里填一套值，SVM 侧在 `svm_adjust_mmio_mask()` 附近填另一套。

AMD 复用格式的额外好处：**NPT 页表本身可以用内核现成的页表操作函数来 dump 和调试**，格式对人眼也是熟悉的。代价是没有独立的 X 位，无法表达"可执行但不可读"这类 EPT 支持的组合。

## 2. memslot：GPA 空间的定义者

### 2.1 数据结构

```c
/* include/linux/kvm_host.h:428 */
struct kvm_memory_slot {
    gfn_t base_gfn;                  /* GPA 起始页帧号 */
    unsigned long npages;            /* 页数 */
    unsigned long *dirty_bitmap;     /* 脏页位图，用于迁移 */
    struct kvm_arch_memory_slot arch;
    unsigned long userspace_addr;    /* 对应的 HVA 起点 */
    u32 flags;
    short id;
    u16 as_id;                       /* 地址空间 ID：0=普通，1=SMM */
};

/* include/linux/kvm_host.h:528 */
struct kvm_memslots {
    u64 generation;
    short id_to_index[KVM_MEM_SLOTS_NUM];
    atomic_t last_used_slot;
    int used_slots;
    struct kvm_memory_slot memslots[];   /* 按 base_gfn 降序排列 */
};
```

注意 `as_id`：x86 上有**两个**地址空间，普通模式和 SMM（System Management Mode）。SMM 有自己独立的一套 memslot，因为 SMRAM 对普通模式必须不可见。

`generation` 是一个全局递增计数器，任何 memslot 变更都会让它加一。它的用途在第 5 节（MMIO SPTE 失效）。

### 2.2 查找：降序数组上的二分

`memslots[]` 按 `base_gfn` **降序**排列（不是升序，这一点很反直觉）：

```c
/* include/linux/kvm_host.h:1230 */
static inline struct kvm_memory_slot *
search_memslots(struct kvm_memslots *slots, gfn_t gfn, int *index)
{
    int start = 0, end = slots->used_slots;
    struct kvm_memory_slot *memslots = slots->memslots;
    struct kvm_memory_slot *slot;

    if (unlikely(!slots->used_slots))
        return NULL;

    while (start < end) {
        int slot = start + (end - start) / 2;

        if (gfn >= memslots[slot].base_gfn)
            end = slot;
        else
            start = slot + 1;
    }

    slot = try_get_memslot(slots, start, gfn);
    if (slot) {
        *index = start;
        return slot;
    }
    return NULL;
}
```

`last_used_slot` 是一个单项缓存：绝大多数缺页都落在同一个大 slot 里（那个覆盖了 Guest 全部 RAM 的槽），先试缓存命中就能跳过二分。

（补充：5.17 之后这套结构被重写成了红黑树 + 区间树，以支持大量 memslot 的场景。5.15 还是数组 + 二分。）

### 2.3 GPA → HVA 的换算与 Spectre 防护

```c
/* include/linux/kvm_host.h:1281 */
static inline unsigned long
__gfn_to_hva_memslot(const struct kvm_memory_slot *slot, gfn_t gfn)
{
    /*
     * The index was checked originally in search_memslots.  To avoid
     * that a malicious guest builds a Spectre gadget out of e.g. page
     * table walks, do not let the processor speculate loads outside
     * the guest's registered memslots.
     */
    unsigned long offset = gfn - slot->base_gfn;
    offset = array_index_nospec(offset, slot->npages);
    return slot->userspace_addr + offset * PAGE_SIZE;
}
```

换算逻辑本身只有一行加法，但 `array_index_nospec()` 值得注意：Guest 可以构造一个越界的 GPA，虽然 `search_memslots` 会拒绝它，但**投机执行可能在边界检查完成之前就用越界的 offset 去访存**，把 Host 内存内容带进缓存，再用侧信道读出来。`array_index_nospec()` 用无分支的掩码运算强制把越界索引钳到 0。

这是虚拟化代码里非常典型的一类防御：**Guest 是不可信输入源，任何来自 Guest 的索引都要当作攻击载荷对待。**

### 2.4 注册路径与惰性

用户态调 `KVM_SET_USER_MEMORY_REGION` 之后，内核做的事情是：

```
   ioctl(vm_fd, KVM_SET_USER_MEMORY_REGION, &region)
        │
        ├─ kvm_vm_ioctl_set_memory_region()
        │     └─ kvm_set_memory_region()
        │           └─ __kvm_set_memory_region()
        │                 ├─ 参数校验：
        │                 │    · guest_phys_addr 页对齐
        │                 │    · memory_size 页对齐、非零（零表示删除）
        │                 │    · userspace_addr 页对齐且 access_ok()
        │                 │    · 不与其它 slot 的 GPA 区间重叠
        │                 ├─ 判定操作类型：CREATE / DELETE / MOVE / FLAGS_ONLY
        │                 ├─ 分配新的 kvm_memslots 数组（RCU 更新）
        │                 ├─ 如果开了 dirty log，分配 dirty_bitmap
        │                 └─ kvm_arch_commit_memory_region()
        │                       └─ 必要时 zap 旧 slot 对应的所有 SPTE
        │
        └─ 返回用户态
```

**这条路径不会建立任何 NPT 映射，也不会 pin 任何物理页。** 它只是在内核里登记了一条"GPA 区间 ↔ HVA 区间"的记录。真正的映射建立要等 Guest 第一次访问该 GPA 触发 `#NPF`。

这意味着一台虚拟机的内存消耗是**双重惰性**的：

```
   用户态 mmap(MAP_ANONYMOUS)     ← 不分配物理页
        │
        │  Guest 第一次访问某 GPA
        ▼
   #NPF → KVM 查 memslot → 算出 HVA
        │
        │  KVM 对该 HVA 调 get_user_pages()
        ▼
   触发 Host 侧的匿名页缺页        ← 此刻才真正分配物理页
        │
        ▼
   拿到 PFN，构造 SPTE 写入 NPT    ← 此刻才建立 GPA → HPA 映射
```

一台配置 8 GB 内存、Guest 内实际只 touch 了 500 MB 的虚拟机，在 Host 上的 RSS 就是 500 MB 左右。这是内存超售的物理基础。

### 2.5 没有 memslot 覆盖的 GPA

这是本卷的核心问题的一半答案：**GPA 空间中哪些区间是 RAM，完全由 memslot 的有无定义。**

一个典型的 x86 虚拟机 GPA 布局：

```
   GPA
   0x0000_0000  ┌──────────────────────────┐
                │  slot 0: 低端 RAM         │  ← 有 memslot
   0x000A_0000  ├──────────────────────────┤
                │  VGA / BIOS 空洞          │  ← 无 memslot
   0x0010_0000  ├──────────────────────────┤
                │  slot 1: 主 RAM 区        │  ← 有 memslot
                │                          │
   0xC000_0000  ├──────────────────────────┤
                │  PCI 空洞 / MMIO 窗口     │  ← 无 memslot
                │  · VirtIO-MMIO 设备寄存器 │
                │  · PCIe BAR              │
   0xFEE0_0000  │  · Local APIC            │
   0xFEC0_0000  │  · IOAPIC                │
   0x1_0000_0000├──────────────────────────┤
                │  slot 2: 4GB 以上 RAM     │  ← 有 memslot
                │                          │
                └──────────────────────────┘
```

用户态 VMM 通过注册（或不注册）memslot 来划出这张图。Guest 访问有 slot 的区间 → 全速运行；访问无 slot 的区间 → 陷出到设备模拟。

**但硬件不认识 memslot。** memslot 是 KVM 的软件概念，硬件只认 NPT 页表项。所以 KVM 必须把"这块地址没有 memslot"这个事实，翻译成一个硬件能理解的页表项形态。这就是第 5 节的内容。

## 3. `#NPF`：从硬件异常到内核入口

### 3.1 硬件侧

当二维漫游在 NPT 这一层失败时，AMD 硬件产生 `#VMEXIT`，`exit_code = SVM_EXIT_NPF (0x400)`，并填两个字段：

- **`exit_info_1`**：错误码。低位复用标准 `#PF` 错误码格式（P/W/U/RSVD/I），高位是 NPF 专用位。
- **`exit_info_2`**：**触发故障的 GPA**。

KVM 的错误码位定义（`arch/x86/include/asm/kvm_host.h:241`）：

```c
#define PFERR_PRESENT_BIT 0     /* 页表项存在但权限不足（0 = 页表项不存在） */
#define PFERR_WRITE_BIT   1     /* 写访问 */
#define PFERR_USER_BIT    2     /* 用户态访问 */
#define PFERR_RSVD_BIT    3     /* ★ 页表项中保留位被置位 */
#define PFERR_FETCH_BIT   4     /* 取指访问 */
#define PFERR_PK_BIT      5     /* Protection Key 违规 */
#define PFERR_SGX_BIT     15
#define PFERR_GUEST_FINAL_BIT 32  /* NPF 专用：故障发生在最终地址翻译 */
#define PFERR_GUEST_PAGE_BIT  33  /* NPF 专用：故障发生在 Guest 页表访问 */
```

**bit 32 / bit 33 是 NPF 独有的**，它们回答了一个二维漫游特有的问题："这次 NPT 失败，是发生在翻译最终目标地址时，还是发生在翻译 Guest 页表本身的地址时？"这个区分在嵌套虚拟化里至关重要——`PFERR_NESTED_GUEST_PAGE`（两位都置）表示 L2 在访问 L1 的页表，KVM 对这种情况有专门的处理（`kvm_mmu_unprotect_page` 后重试）。

**bit 3（RSVD）是本卷的主角**，第 5 节展开。

### 3.2 内核入口

```c
/* arch/x86/kvm/svm/svm.c:1901 */
static int npf_interception(struct kvm_vcpu *vcpu)
{
    struct vcpu_svm *svm = to_svm(vcpu);

    u64 fault_address = svm->vmcb->control.exit_info_2;
    u64 error_code    = svm->vmcb->control.exit_info_1;

    trace_kvm_page_fault(fault_address, error_code);
    return kvm_mmu_page_fault(vcpu, fault_address, error_code,
            static_cpu_has(X86_FEATURE_DECODEASSISTS) ?
                svm->vmcb->control.insn_bytes : NULL,
            svm->vmcb->control.insn_len);
}
```

对照 Intel 侧：

```c
/* arch/x86/kvm/vmx/vmx.c:5272 */
static int handle_ept_violation(struct kvm_vcpu *vcpu)
{
    unsigned long exit_qualification = vmx_get_exit_qual(vcpu);
    gpa_t gpa;
    u64 error_code;
    ...
    gpa = vmcs_read64(GUEST_PHYSICAL_ADDRESS);

    error_code  = (exit_qualification & EPT_VIOLATION_ACC_READ)  ? PFERR_USER_MASK  : 0;
    error_code |= (exit_qualification & EPT_VIOLATION_ACC_WRITE) ? PFERR_WRITE_MASK : 0;
    error_code |= (exit_qualification & EPT_VIOLATION_ACC_INSTR) ? PFERR_FETCH_MASK : 0;
    ...
    return kvm_mmu_page_fault(vcpu, gpa, error_code, NULL, 0);
}
```

三处差异一目了然：Intel 要用 `vmcs_read64` 才能拿到 GPA；错误码格式不同，必须手工翻译成 KVM 内部格式；最后两个参数是 `NULL, 0`——**Intel 无法提供指令字节**。

另外 Intel 有两种 EPT 相关退出：**EPT Violation（48）** 表示权限不足或页不存在；**EPT Misconfiguration（49）** 表示 EPT 页表项本身格式非法（比如设了保留位）。AMD 把这两种情况合并成一个 `#NPF`，用错误码的 RSVD 位区分。这个差异直接影响了 MMIO 识别的实现（第 5.3 节）。

### 3.3 分发

```c
/* arch/x86/kvm/mmu/mmu.c:5270 */
int kvm_mmu_page_fault(struct kvm_vcpu *vcpu, gpa_t cr2_or_gpa, u64 error_code,
                       void *insn, int insn_len)
{
    int r, emulation_type = EMULTYPE_PF;
    bool direct = vcpu->arch.mmu->direct_map;

    r = RET_PF_INVALID;

    /* ★ 快速路径：保留位故障 = MMIO SPTE 命中 */
    if (unlikely(error_code & PFERR_RSVD_MASK)) {
        r = handle_mmio_page_fault(vcpu, cr2_or_gpa, direct);
        if (r == RET_PF_EMULATE)
            goto emulate;
    }

    if (r == RET_PF_INVALID) {
        r = kvm_mmu_do_page_fault(vcpu, cr2_or_gpa,
                                  lower_32_bits(error_code), false);
        ...
    }

    if (r < 0)
        return r;
    if (r != RET_PF_EMULATE)
        return 1;                    /* 修好了，直接重入 Guest */
    ...
emulate:
    return x86_emulate_instruction(vcpu, cr2_or_gpa, emulation_type, insn, insn_len);
}
```

返回值的语义定义在 `mmu_internal.h`：

```c
enum {
    RET_PF_RETRY = 0,    /* 状态变了，让 Guest 重新执行触发指令 */
    RET_PF_EMULATE,      /* 这是 MMIO，需要软件模拟这条指令 */
    RET_PF_INVALID,      /* 内部标记：还没处理 */
    RET_PF_FIXED,        /* 已建立映射 */
    RET_PF_SPURIOUS,     /* 虚假缺页：别的 vCPU 已经修好了 */
};
```

`RET_PF_SPURIOUS` 在 SMP 虚拟机上很常见：两个 vCPU 同时访问同一个未映射的 GPA，都陷出，其中一个建好了 SPTE，另一个发现"要写的值和已有的一样"。

## 4. 建表：从 GPA 到 SPTE 的完整链路

### 4.1 主干

```c
/* arch/x86/kvm/mmu/mmu.c:3965，节选主干 */
static int direct_page_fault(struct kvm_vcpu *vcpu, gpa_t gpa, u32 error_code,
                             bool prefault, int max_level, bool is_tdp)
{
    bool is_tdp_mmu_fault = is_tdp_mmu(vcpu->arch.mmu);
    bool write = error_code & PFERR_WRITE_MASK;
    gfn_t gfn = gpa >> PAGE_SHIFT;
    unsigned long mmu_seq;
    kvm_pfn_t pfn;
    hva_t hva;
    int r;

    /* 1. Guest 页表被写保护跟踪？（影子页表场景） */
    if (page_fault_handle_page_track(vcpu, error_code, gfn))
        return RET_PF_EMULATE;

    /* 2. 快速路径：只需翻转 SPTE 的写权限位，无锁 cmpxchg 搞定 */
    r = fast_page_fault(vcpu, gpa, error_code);
    if (r != RET_PF_INVALID)
        return r;

    r = mmu_topup_memory_caches(vcpu, false);
    if (r) return r;

    /* 3. ★ 抓取 mmu_notifier 序列号，用于后面检测竞态 */
    mmu_seq = vcpu->kvm->mmu_notifier_seq;
    smp_rmb();

    /* 4. GPA → memslot → HVA → PFN */
    if (kvm_faultin_pfn(vcpu, prefault, gfn, gpa, &pfn, &hva, write, &map_writable, &r))
        return r;

    /* 5. 异常 PFN 处理（错误页 / 无 memslot） */
    if (handle_abnormal_pfn(vcpu, is_tdp ? 0 : gpa, gfn, pfn, ACC_ALL, &r))
        return r;

    r = RET_PF_RETRY;

    /* 6. ★ 注意：TDP MMU 只取读锁 */
    if (is_tdp_mmu_fault)
        read_lock(&vcpu->kvm->mmu_lock);
    else
        write_lock(&vcpu->kvm->mmu_lock);

    /* 7. ★ 竞态检测：拿锁期间 Host 有没有回收/迁移这个 HVA？ */
    if (!is_noslot_pfn(pfn) && mmu_notifier_retry_hva(vcpu->kvm, mmu_seq, hva))
        goto out_unlock;

    r = make_mmu_pages_available(vcpu);
    if (r) goto out_unlock;

    /* 8. 建表 */
    if (is_tdp_mmu_fault)
        r = kvm_tdp_mmu_map(vcpu, gpa, error_code, map_writable, max_level, pfn, prefault);
    else
        r = __direct_map(vcpu, gpa, error_code, map_writable, max_level, pfn, prefault, is_tdp);

out_unlock:
    if (is_tdp_mmu_fault)
        read_unlock(&vcpu->kvm->mmu_lock);
    else
        write_unlock(&vcpu->kvm->mmu_lock);
    kvm_release_pfn_clean(pfn);
    return r;
}
```

### 4.2 第 3、7 步：与 Host 内存管理的竞态

这两步是整段代码里最微妙的部分，值得单独讲。

Host 的内存管理子系统会在 KVM 不知情的情况下改变 HVA → PFN 的映射：页面回收（swap out）、THP 折叠与分裂、KSM 页面合并、内存压缩（compaction）迁移页面、`madvise(MADV_DONTNEED)`。如果 KVM 在第 4 步拿到 PFN 之后、第 8 步写入 SPTE 之前，Host 把那个物理页回收了，KVM 就会往 NPT 里写入一个指向**已经被别人使用的物理页**的映射——这是一个直接的内存破坏。

解决方案是 `mmu_notifier`。KVM 在创建虚拟机时注册了一组回调：

```c
/* virt/kvm/kvm_main.c:790 */
static const struct mmu_notifier_ops kvm_mmu_notifier_ops = {
    .invalidate_range_start = kvm_mmu_notifier_invalidate_range_start,
    .invalidate_range_end   = kvm_mmu_notifier_invalidate_range_end,
    .clear_flush_young      = kvm_mmu_notifier_clear_flush_young,
    .clear_young            = kvm_mmu_notifier_clear_young,
    .test_young             = kvm_mmu_notifier_test_young,
    .change_pte             = kvm_mmu_notifier_change_pte,
    .release                = kvm_mmu_notifier_release,
};
```

Host MM 在动任何用户页映射之前，会先调用 `invalidate_range_start`，KVM 借此把对应的 SPTE 全部清掉（`kvm_unmap_gfn_range`），并**递增 `mmu_notifier_seq`**。

于是第 3 步和第 7 步构成了一个经典的**序列号乐观锁**：

```
   vCPU 线程                              Host MM 线程（比如 kswapd）
   ─────────────────────────────────────────────────────────────────
   mmu_seq = kvm->mmu_notifier_seq
   smp_rmb()
        │
   gfn_to_pfn() ──► 拿到 PFN=X
        │                                  invalidate_range_start()
        │                                     ├─ 清掉相关 SPTE
        │                                     ├─ mmu_notifier_count++
        │                                     └─ mmu_notifier_seq++
        │                                  回收物理页 X
   read_lock(mmu_lock)
   mmu_notifier_retry_hva(kvm, mmu_seq, hva)
        │   发现 seq 变了 → 返回 true
        ▼
   goto out_unlock，返回 RET_PF_RETRY
   → Guest 重新执行触发指令，重来一遍
```

**这是虚拟化与 Host 内存管理协同的核心机制。** 它保证了 KVM 的 NPT 不会持有过期的物理页引用，从而使得 Guest 内存可以像普通匿名内存一样被 swap、被 KSM 合并、被 THP 折叠——虚拟化没有在 Host 的内存管理体系里开一个特权洞。

### 4.3 第 4 步：GPA → PFN

```c
/* arch/x86/kvm/mmu/mmu.c:3906，节选 */
static bool kvm_faultin_pfn(struct kvm_vcpu *vcpu, bool prefault, gfn_t gfn,
                            gpa_t cr2_or_gpa, kvm_pfn_t *pfn, hva_t *hva,
                            bool write, bool *writable, int *r)
{
    struct kvm_memory_slot *slot = kvm_vcpu_gfn_to_memslot(vcpu, gfn);

    /* slot 正在被删除或移动 → 重试 */
    if (slot && (slot->flags & KVM_MEMSLOT_INVALID))
        goto out_retry;

    if (!kvm_is_visible_memslot(slot)) {
        /* ★ 没有 memslot：返回特殊 PFN */
        if (is_guest_mode(vcpu)) {
            *pfn = KVM_PFN_NOSLOT;
            *writable = false;
            return false;
        }
        ...
    }

    *pfn = __gfn_to_pfn_memslot(slot, gfn, false, &async, write, writable, hva);
    ...
}
```

`__gfn_to_pfn_memslot()` 内部：先用 `__gfn_to_hva_memslot()` 算出 HVA，再调 `hva_to_pfn()`，后者本质上是 `get_user_pages_unlocked()` 的封装——**走的是 Host 完全标准的用户页缺页路径**。如果那个 HVA 还没有物理页（用户态刚 `mmap` 完没碰过），这里就会触发 Host 侧的匿名页分配。

`slot == NULL` 时返回 `KVM_PFN_NOSLOT`，这是一个不对应任何物理页的哨兵值。**这条分支就是"这块 GPA 是设备"的判定点。**

### 4.4 第 8 步：TDP MMU 的无锁建表

先说 `read_lock` 那个反直觉的地方：**建立页表映射居然只需要读锁。**

这是 TDP MMU（5.10 引入，5.15 已是默认）相对传统影子 MMU 的核心改进。传统 MMU 用一把写锁保护整棵页表树，在 128 vCPU 的大虚拟机上，启动阶段成千上万个并发缺页全部串行化在这把锁上。TDP MMU 的做法是：

1. 页表树的遍历用 **RCU** 保护（`rcu_read_lock()` + `rcu_dereference()`）；
2. 每个 SPTE 的修改用 **`cmpxchg64` 原子操作**完成；
3. `mmu_lock` 的读锁只用来排除"整棵树被拆掉"这类结构性操作。

```c
/* arch/x86/kvm/mmu/tdp_mmu.c:989，节选主干 */
int kvm_tdp_mmu_map(struct kvm_vcpu *vcpu, gpa_t gpa, u32 error_code,
                    int map_writable, int max_level, kvm_pfn_t pfn, bool prefault)
{
    struct tdp_iter iter;
    gfn_t gfn = gpa >> PAGE_SHIFT;
    int level, req_level;

    /* 尝试用大页：检查 Host 侧该 HVA 是不是 THP、memslot 对齐是否允许 */
    level = kvm_mmu_hugepage_adjust(vcpu, gfn, max_level, &pfn,
                                    huge_page_disallowed, &req_level);

    rcu_read_lock();

    tdp_mmu_for_each_pte(iter, mmu, gfn, gfn + 1) {
        if (iter.level == level)
            break;                       /* 到达目标级，跳出去建叶子项 */

        /* 上层已有大页映射，但这次需要更细粒度 → 拆掉它 */
        if (is_shadow_present_pte(iter.old_spte) && is_large_pte(iter.old_spte)) {
            if (!tdp_mmu_zap_spte_atomic(vcpu->kvm, &iter))
                break;
            iter.old_spte = READ_ONCE(*rcu_dereference(iter.sptep));
        }

        /* 中间级不存在 → 分配一页页表，原子挂上去 */
        if (!is_shadow_present_pte(iter.old_spte)) {
            if (is_removed_spte(iter.old_spte))
                break;                   /* 别的线程正在拆，放弃重试 */

            sp = alloc_tdp_mmu_page(vcpu, iter.gfn, iter.level - 1);
            new_spte = make_nonleaf_spte(sp->spt, !shadow_accessed_mask);

            if (tdp_mmu_set_spte_atomic_no_dirty_log(vcpu->kvm, &iter, new_spte)) {
                tdp_mmu_link_page(vcpu->kvm, sp, ...);
            } else {
                tdp_mmu_free_sp(sp);     /* cmpxchg 失败：别人抢先建了 */
                break;
            }
        }
    }
    ...
    ret = tdp_mmu_map_handle_target_level(vcpu, write, map_writable, &iter, pfn, prefault);
    rcu_read_unlock();
    return ret;
}
```

几个并发设计要点：

- **`is_removed_spte()`**：TDP MMU 用一个特殊的"已移除"哨兵值来标记正在被拆除的页表项。看到它就说明有别的线程在做冲突操作，当前线程直接放弃，让 Guest 重新触发缺页。这是一种无锁数据结构里常见的"冻结标记"手法。
- **`cmpxchg` 失败即放弃**。分配了页表页但 `cmpxchg` 失败，说明另一个 vCPU 抢先建好了同样的中间级，本线程把刚分配的页释放掉、退出循环即可——这次缺页会返回 `RET_PF_RETRY`，Guest 重试时会走到已经建好的路径上。
- **`kvm_mmu_hugepage_adjust()`** 决定这次映射用多大的页。它要同时满足三个条件：Host 侧该 HVA 确实由一个 THP 支撑、memslot 的 `base_gfn` 与 `userspace_addr` 在大页粒度上对齐、以及没有开启细粒度脏页跟踪。任何一条不满足就降级到 4 KB。

### 4.5 构造叶子 SPTE

```c
/* arch/x86/kvm/mmu/spte.c:92，节选 */
int make_spte(struct kvm_vcpu *vcpu, unsigned int pte_access, int level,
              gfn_t gfn, kvm_pfn_t pfn, u64 old_spte, bool speculative,
              bool can_unsync, bool host_writable, bool ad_disabled, u64 *new_spte)
{
    u64 spte = SPTE_MMU_PRESENT_MASK;          /* bit 11，KVM 私有标记 */

    if (ad_disabled)
        spte |= SPTE_TDP_AD_DISABLED_MASK;     /* bit 52-53，KVM 私有 */

    spte |= shadow_present_mask;               /* NPT: bit 0 (P) */
    if (!speculative)
        spte |= spte_shadow_accessed_mask(spte);

    /* NX huge page 缓解措施：大页不给执行权限 */
    if (level > PG_LEVEL_4K && (pte_access & ACC_EXEC_MASK) && is_nx_huge_page_enabled())
        pte_access &= ~ACC_EXEC_MASK;

    if (pte_access & ACC_EXEC_MASK)
        spte |= shadow_x_mask;                 /* NPT: 0（无 X 位）；EPT: bit 2 */
    else
        spte |= shadow_nx_mask;                /* NPT: bit 63 (NX)；EPT: 0 */

    if (pte_access & ACC_USER_MASK)
        spte |= shadow_user_mask;              /* NPT: bit 2 (U/S)；EPT: 0 */

    if (level > PG_LEVEL_4K)
        spte |= PT_PAGE_SIZE_MASK;             /* bit 7 (PS)，大页 */

    if (tdp_enabled)
        spte |= static_call(kvm_x86_get_mt_mask)(vcpu, gfn, kvm_is_mmio_pfn(pfn));

    if (host_writable)
        spte |= shadow_host_writable_mask;
    else
        pte_access &= ~ACC_WRITE_MASK;

    if (!kvm_is_mmio_pfn(pfn))
        spte |= shadow_me_mask;                /* AMD SME 内存加密位 */

    spte |= (u64)pfn << PAGE_SHIFT;            /* ★ 物理页帧号 */

    if (pte_access & ACC_WRITE_MASK) {
        spte |= PT_WRITABLE_MASK | shadow_mmu_writable_mask;
        ...
    }
    ...
    *new_spte = spte;
    return ret;
}
```

值得注意的是 **KVM 在 SPTE 里塞了自己的私有位**：`SPTE_MMU_PRESENT_MASK` 用 bit 11，`SPTE_TDP_AD_*` 用 bit 52-53。这些位在硬件看来是"忽略位"或"保留位"，但 KVM 用它们区分"硬件认为存在"和"KVM 认为存在"这两种不同的状态。头文件里的注释解释了为什么选 bit 11 而不是 bit 56：

> Use bit 11, as it is ignored by all flavors of SPTEs and checking a low bit often generates better code than for a high bit, e.g. 56+. MMU present checks are pervasive enough that the improved code generation is noticeable in KVM's footprint.

用低位可以让编译器生成 `test $0x800, %eax` 这样的短指令，而高位需要额外的立即数加载。这个优化能在整个内核镜像的体积上看出来——是典型的核心路径微优化。

## 5. MMIO 识别：把"这是设备"编码进页表项

现在回到本卷开篇的问题。

### 5.1 朴素方案为什么不行

最直接的想法是：不给 MMIO 地址建任何 SPTE，让它每次访问都产生 `#NPF`，KVM 每次都查一遍 memslot，发现没有就当作 MMIO。

问题在于 `#NPF` 的处理路径太长了。上一节那条 `direct_page_fault` 链路要做：page track 检查、fast page fault 尝试、memory cache 补充、`mmu_notifier_seq` 抓取、`kvm_vcpu_gfn_to_memslot()` 二分查找、`kvm_faultin_pfn`、拿锁、竞态检查……而对于一个 MMIO 访问，这一整套的结论永远是同一个："没有 memslot，去模拟指令"。

一个跑 VirtIO 的虚拟机，MMIO 访问是热路径中的热路径。为它跑一遍完整的缺页处理，浪费的周期非常可观。

### 5.2 保留位技巧

KVM 的方案是：**给 MMIO 地址安装一个"故意非法"的 SPTE**。

```c
/* arch/x86/kvm/mmu/spte.c:54 */
u64 make_mmio_spte(struct kvm_vcpu *vcpu, u64 gfn, unsigned int access)
{
    u64 gen = kvm_vcpu_memslots(vcpu)->generation & MMIO_SPTE_GEN_MASK;
    u64 spte = generation_mmio_spte_mask(gen);
    u64 gpa = gfn << PAGE_SHIFT;

    WARN_ON_ONCE(!shadow_mmio_value);

    access &= shadow_mmio_access_mask;
    spte |= shadow_mmio_value | access;
    spte |= gpa | shadow_nonpresent_or_rsvd_mask;
    spte |= (gpa & shadow_nonpresent_or_rsvd_mask) << SHADOW_NONPRESENT_OR_RSVD_MASK_LEN;

    return spte;
}
```

在 AMD 上，`shadow_mmio_value` 的构造是：

```c
/* arch/x86/kvm/svm/svm.c:880，svm_adjust_mmio_mask() */
enc_bit  = cpuid_ebx(0x8000001f) & 0x3f;       /* SME 加密位位置 */
mask_bit = boot_cpu_data.x86_phys_bits;        /* 物理地址位宽，如 48 */

if (enc_bit == mask_bit)
    mask_bit++;

/*
 * If the mask bit location is below 52, then some bits above the
 * physical addressing limit will always be reserved, so use the
 * rsvd_bits() function to generate the mask. This mask, along with
 * the present bit, will be used to generate a page fault with
 * PFER.RSV = 1.
 */
mask = (mask_bit < 52) ? rsvd_bits(mask_bit, 51) | PT_PRESENT_MASK : 0;

kvm_mmu_set_mmio_spte_mask(mask, mask, PT_WRITABLE_MASK | PT_USER_MASK);
```

拆解这段：`x86_phys_bits` 是这颗 CPU 实际支持的物理地址位数（典型值 48）。页表项里 bit 51:12 是物理地址字段，但硬件只用低 48 位——**bit 51:48 是硬件强制要求为 0 的保留位**。KVM 把这几位全置 1，再加上 Present 位，就构造出了一个"存在但格式非法"的页表项。

```
   一个 MMIO SPTE 的位布局（AMD，x86_phys_bits = 48）

    63           52 51      48 47                    12 11  3 2 1 0
   ┌───────────────┬──────────┬───────────────────────┬──────┬─┬─┬─┐
   │ MMIO gen 高位  │ 1 1 1 1  │      GPA 的高位部分    │ gen低│U│W│1│
   │  (bit 62:52)  │ ↑保留位  │                       │ 位   │ │ │↑│
   └───────────────┴──────────┴───────────────────────┴──────┴─┴─┴─┘
                     置 1 → 硬件漫游到这里时                      Present=1
                     判定"保留位违规"                             （让硬件真的去看它）
```

**硬件行为**：二维漫游走到这个 SPTE，发现 Present=1（所以不是"页不存在"），但保留位非零 → 立刻产生 `#NPF`，并且在 `exit_info_1` 里置上 **`PFERR_RSVD` (bit 3)**。

**KVM 侧**：`kvm_mmu_page_fault()` 开头那个 `if (unlikely(error_code & PFERR_RSVD_MASK))` 直接命中，走进 `handle_mmio_page_fault()`：

```c
/* arch/x86/kvm/mmu/mmu.c:3824 */
static int handle_mmio_page_fault(struct kvm_vcpu *vcpu, u64 addr, bool direct)
{
    u64 spte;

    if (mmio_info_in_cache(vcpu, addr, direct))
        return RET_PF_EMULATE;               /* 更快：per-vCPU 单项缓存命中 */

    reserved = get_mmio_spte(vcpu, addr, &spte);

    if (is_mmio_spte(spte)) {
        gfn_t gfn = get_mmio_spte_gfn(spte);         /* 从 SPTE 里取回 GPA */
        unsigned int access = get_mmio_spte_access(spte);

        if (!check_mmio_spte(vcpu, spte))            /* 检查 generation */
            return RET_PF_INVALID;

        vcpu_cache_mmio_info(vcpu, addr, gfn, access);
        return RET_PF_EMULATE;
    }
    ...
}
```

**整条路径被压缩成：查一次 per-vCPU 缓存 → 命中 → 直接去模拟指令。** 完全跳过 memslot 查找、`gfn_to_pfn`、锁、竞态检查。

### 5.3 generation：memslot 变更时如何让 MMIO SPTE 失效

MMIO SPTE 有一个正确性问题：它是根据"当前没有 memslot 覆盖这个 GPA"这个事实建立的。如果用户态之后注册了一个覆盖该 GPA 的 memslot（比如热插拔内存、或者把一段 MMIO 窗口改成 RAM），这些 MMIO SPTE 就变成了错误的映射。

暴力方案是每次 memslot 变更就遍历整棵 NPT 清掉所有 MMIO SPTE——代价太高。

KVM 的方案是把 **memslot 的 generation 编码进 SPTE 本身**：

```c
/* arch/x86/kvm/mmu/spte.h */
#define MMIO_SPTE_GEN_LOW_START     3
#define MMIO_SPTE_GEN_LOW_END       10      /* bit 10:3，8 位 */
#define MMIO_SPTE_GEN_HIGH_START    52
#define MMIO_SPTE_GEN_HIGH_END      62      /* bit 62:52，11 位 */

static_assert(MMIO_SPTE_GEN_LOW_BITS == 8 && MMIO_SPTE_GEN_HIGH_BITS == 11);
static_assert(!(SPTE_MMU_PRESENT_MASK &
                (MMIO_SPTE_GEN_LOW_MASK | MMIO_SPTE_GEN_HIGH_MASK)));
```

19 位的 generation 被拆成两段塞进 SPTE 里那些硬件不关心的位。`check_mmio_spte()` 比对 SPTE 里的 generation 和当前 `kvm_memslots()->generation`：不一致就返回 `RET_PF_INVALID`，走完整的建表路径重新判定。

**这是一个精妙的惰性失效设计**：memslot 变更时只需要把全局 generation 加一（O(1)），所有陈旧的 MMIO SPTE 会在下次被访问时自然失效并重建。那两个 `static_assert` 保证了 generation 占用的位不与 KVM 的私有 present 标记冲突——这类编译期断言在 SPTE 位分配这种"寸土寸金"的场景下是必需的防线。

### 5.4 Intel 的对照方案

Intel 的 EPT 页表项格式与 x86 页表完全不同，没有"物理地址位宽之上的保留位"这个天然的钩子。KVM 用的是另一个非法组合：

```c
/* arch/x86/kvm/mmu/spte.c:316 */
kvm_mmu_set_mmio_spte_mask(VMX_EPT_MISCONFIG_WX_VALUE,
                           VMX_EPT_MISCONFIG_WX_VALUE,
                           0);
```

`VMX_EPT_MISCONFIG_WX_VALUE` 是 "Write=1, Execute=1, Read=0" 的组合。EPT 规范规定 **Write 权限不能在没有 Read 权限的情况下单独存在**——这是一个格式非法的 EPT 项。硬件漫游到它会产生 **EPT Misconfiguration（退出码 49）**，而不是普通的 EPT Violation。KVM 的 `handle_ept_misconfig()` 就直接走 MMIO 模拟路径。

两家用了完全不同的硬件钩子（AMD：地址保留位；Intel：非法权限组合）来实现同一个软件优化，这是典型的"同一设计意图落到不同硬件规范上"的案例。

### 5.5 完整的判定链路

把整条链路串起来：

```
   Guest:  mov %eax, 0xd0000000(%rbx)      ← 写 VirtIO-MMIO 设备寄存器
              │
              │ 硬件：Guest 页表漫游 → GPA = 0xd0000000
              │       NPT 漫游 → 走到叶子 SPTE
              ▼
        ┌─────────────────────────────────────────────┐
        │ 这个 GPA 之前访问过吗？                       │
        └─────────────────────────────────────────────┘
              │                              │
        否（首次）                       是（已装 MMIO SPTE）
              │                              │
              │ NPT 叶子项为空                │ NPT 叶子项 = MMIO SPTE
              │ → #NPF, RSVD=0               │ → #NPF, RSVD=1
              ▼                              ▼
     kvm_mmu_page_fault()             kvm_mmu_page_fault()
        RSVD 未置位 → 走完整路径          RSVD 置位 → 快速路径
              │                              │
     direct_page_fault()             handle_mmio_page_fault()
        │                                    │
     kvm_faultin_pfn()                 mmio_info_in_cache() 命中
        │  gfn_to_memslot() → NULL           │
        │  pfn = KVM_PFN_NOSLOT              │
        ▼                                    │
     handle_abnormal_pfn()                   │
        │  is_noslot_pfn(pfn) → true         │
        │  vcpu_cache_mmio_info()            │
        ▼                                    │
     kvm_tdp_mmu_map()                       │
        └─ tdp_mmu_map_handle_target_level() │
             │  is_noslot_pfn → 装 MMIO SPTE │
             │  返回 RET_PF_EMULATE          │
             ▼                               ▼
        ┌─────────────────────────────────────────────┐
        │  RET_PF_EMULATE                             │
        │  → x86_emulate_instruction()                │
        │     解码这条 mov，取出要写的值               │
        │     → 内核内设备？ 用户态设备？（见卷三）     │
        └─────────────────────────────────────────────┘
```

第一次访问付出完整缺页的代价并留下一个 MMIO SPTE，之后每次访问都走 RSVD 快速路径。**这就是"硬件如何知道哪些地址是设备"的完整答案：不是靠表，是靠一个故意构造的非法页表项，把软件的判定结果缓存进了硬件的漫游路径上。**

## 6. 从这里到设备虚拟化

本卷把内存虚拟化的机制拆完了：

1. 三层地址、二维漫游的 24 次访存、NPT 与 EPT 的格式分歧及其在 KVM 代码里表现为 `shadow_*_mask` 全局变量。
2. `memslot` 是 GPA 空间的定义者：注册 memslot 的区间是 RAM，未覆盖的区间是设备。注册本身是惰性的，物理页分配和 NPT 建表都推迟到第一次访问。
3. `#NPF` 的完整生命周期：硬件填 `exit_info_1/2` → `npf_interception` → `kvm_mmu_page_fault` → `direct_page_fault` → `kvm_faultin_pfn` → `kvm_tdp_mmu_map` → `make_spte`。
4. `mmu_notifier_seq` 乐观锁让 Guest 内存能够正常参与 Host 的 swap / KSM / THP。
5. TDP MMU 用 RCU 遍历 + `cmpxchg` 建表，把 `mmu_lock` 降级成读锁，这是大规格虚拟机的可扩展性基础。
6. MMIO 通过"故意非法的 SPTE"识别：AMD 用物理地址保留位触发 `PFERR_RSVD`，Intel 用非法的 W/X 权限组合触发 EPT Misconfig；generation 编码进 SPTE 实现 O(1) 的惰性失效。

到这里，Guest 的一次设备访问已经被硬件和 KVM 一路押送到了 `x86_emulate_instruction()` 的门口。**但 KVM 本身几乎不模拟设备。**

卷三从这个门口继续：KVM 与用户态之间那份基于共享内存的 ABI 契约（`struct kvm_run`、三层文件描述符、PIO 数据页）、指令模拟器如何还原出 Guest 要写的数据、`KVM_EXIT_MMIO` 与 `KVM_EXIT_IO` 两条路径的成本差异、以及一个最小 VMM 从 `open("/dev/kvm")` 到接住第一次设备访问的完整实现。
