## 一、两份手册，冲突时听谁的

PIIX4 是 KVM 和 QEMU 默认模拟的南桥，它对 8259A 做了三件事：把两颗芯片的级联关系焊死（从片 INT 接主片 IR2，PIIX4 4.2.2.3），用 ELCR 取代 ICW1 的 LTIM 位来逐根选择边沿/电平（PIIX4 4.2.2.1、8.6.5），以及规定某些 ICW 位必须取固定值（比如 ICW4 的 μPM 必须为 1，PIIX4 4.2.2.5）。这些都是约束，照做即可。

但两份手册有两处直接冲突：

| 问题 | 8259A | PIIX4 | 按谁 |
|---|---|---|---|
| 被屏蔽的 IRQ 置不置 IRR | IRR 不受 IMR 影响 | OCW1 说被屏蔽的 IRQ 不置 IRR | 8259A |
| OCW3 bit 6、bit 5 | D6 = ESMM，D5 = SMM（图 8） | 文字写成 SMM、ESMM | 8259A |

第一处按 8259A，是因为 Linux 依赖它。Linux 把一根 ISA IRQ 从 PIC 交给 IOAPIC 时：

```c
/* arch/x86/kernel/apic/io_apic.c */
static unsigned int startup_ioapic_irq(struct irq_data *data)
{
    ...
    if (irq < nr_legacy_irqs()) {
        legacy_pic->mask(irq);
        if (legacy_pic->irq_pending(irq))     /* 读 IRR */
            was_pending = 1;
    }
    __unmask_ioapic(data->chip_data);
    ...
}
```

先在 PIC 上屏蔽，再读 PIC 的 IRR 看这根线上有没有挂着的请求，有就让中断子系统补发一次。如果 IMR 挡住了 IRR，这个检查永远读到 0，切换瞬间到来的边沿就丢了。这是 Linux 写给真实硬件的代码，说明真实的 PIIX4 行为和 8259A 手册一致，PIIX4 的那句文字是笔误。第二处同理，按芯片原始手册的位图（单元测试 `test_special_mask` 和变异体 `pic-esmm-ignored` 守着它）。

## 二、priority cell：IRR 不是一个普通的寄存器

### 2.1 图 9

《中断·原理篇》把 IRR 说成“记录哪些线上有请求在等”。按这个理解，边沿模式就是“看到上升沿把 IRR 置 1，INTA 时清 0”。可是数据手册第 4 页有一句：

> IR inputs must remain high until after the falling edge of the first INTA.

如果 IRR 是一个“看到边沿就置 1”的锁存器，线什么时候放低都无所谓，为什么要求保持到 INTA？答案在图 9，它画了每一根 IR 的内部电路（priority cell）：

```text
            ┌────────────┐
  IR ──┬───▶│ edge sense │──armed──┐
       │    │   latch    │         ▼
       │    └────────────┘      ┌──────┐   ┌──────────────┐
       │                LTIM ──▶│  OR  │──▶│              │
       │                        └──────┘   │   request    │
       └──────────────────────────────────▶│   latch      │──▶ IRR
                                           │ (transparent)│
                                           └──────────────┘
      edge sense latch：IR 为低时置位（武装），ISR 置位或 ICW1 时清零
      request latch：透明锁存器，D = IR & (LTIM | armed)
```

request latch 是透明的：它的输出跟着输入走，而输入是 `IR & (LTIM | armed)`。所以：

- **电平模式**（LTIM=1，在 PIIX4 上是 ELCR 对应位为 1）：IRR 就是 IR 本身。线高着就有请求，线落下请求就没了。
- **边沿模式**：edge sense latch 在 IR 为低时被“武装”，IR 升起后 `IR & armed` 为 1，IRR 置位。但 IRR 仍然跟着 IR 走：IR 在 INTA 之前落下，IRR 就跟着消失。INTA 置 ISR 时 edge sense latch 清零，此后即使 IR 一直高着，IRR 也是 0，直到 IR 落下再升起重新武装。

“边沿”其实是“IR 为高，且自从上次被服务以后落下过”。手册那句“必须保持到 INTA”说的就是透明锁存器的后果。

### 2.2 实现：IRR 不存，现算

既然 IRR 是线电平和两个锁存器的组合，就不单独存它：

```c
static uint8_t irr(const struct pic8259 *c)
{
    return c->line & (c->elcr | c->armed);
}

static void set_line(struct pic8259 *c, int irq, int level)
{
    uint8_t bit = 1u << irq;

    if (level) {
        c->line |= bit;
    } else {
        c->line &= ~bit;
        c->armed |= bit;       /* IR 为低：武装 */
    }
}

static void ack(struct pic8259 *c, int irq)    /* INTA 第一个脉冲 */
{
    uint8_t bit = 1u << irq;

    c->isr |= bit;
    c->armed &= ~bit;          /* ISR 置位：解除武装 */
    ...
}
```

单元测试 `test_edge_rules` 的第一个用例就是手册那句话：边沿请求在 INTA 之前落下，INTA 拿到的是伪中断（IR7 的向量，ISR 不变）。变异体 `pic-inta-keeps-armed`（INTA 不解除武装，于是高着的线会反复请求）和 `pic-ignores-elcr`（不看 ELCR，全部按边沿）都被挡下。

### 2.3 伪中断

INTA 时如果已经没有请求（线在 INT 拉高之后、INTA 之前落下，或者被屏蔽了），8259A 交出 IR7 的向量，但不置 ISR（第 7 页）。这就是 Linux 日志里偶尔出现的“spurious 8259A interrupt: IRQ7”的来源。实现里两颗芯片各有一个 `spurious[]` 计数，变异体 `pic-spurious-sets-isr` 守着“不置 ISR”这一条：要是置了，guest 不会对一个它认为是伪中断的 IRQ7 写 EOI，IR7 的 ISR 就卡住，挡掉所有优先级更低的中断。

## 三、初始化：ICW1 到 ICW4

### 3.1 状态机

ICW 和 OCW 共用两个端口，靠写的端口、数据的某几位和初始化进度区分（图 6）：

```text
命令端口（A0=0）：bit 4 = 1 → ICW1，开始初始化
                  bit 4 = 0, bit 3 = 1 → OCW3
                  bit 4 = 0, bit 3 = 0 → OCW2
数据端口（A0=1）：初始化进行中 → 依次是 ICW2、ICW3（级联时）、ICW4（IC4=1 时）
                  否则 → OCW1（IMR）
```

```c
static void write_data(struct pic8259 *c, uint8_t val)
{
    switch (c->init_state) {
    case 1:                                    /* ICW2 */
        c->vector_base = val & 0xF8;
        c->init_state = !c->single ? 2 : c->need_icw4 ? 3 : 0;
        break;
    case 2:                                    /* ICW3 */
        c->icw3 = val;
        c->init_state = c->need_icw4 ? 3 : 0;
        break;
    case 3:                                    /* ICW4 */
        c->auto_eoi = val & 0x02;
        c->sfnm = val & 0x10;
        c->init_state = 0;
        break;
    default:                                   /* OCW1 */
        c->imr = val;
        break;
    }
}
```

Linux 的 `init_8259A`（`arch/x86/kernel/i8259.c`）写的就是这个序列：主片 `0x11`（ICW1：边沿、级联、要 ICW4）、`0x30`（ICW2：向量基址）、`0x04`（ICW3：IR2 接了从片）、`0x01`（ICW4：8086 模式），从片 `0x11`、`0x38`、`0x02`（ICW3：我的级联号是 2）、`0x01`。用 `--trace-pio` 能在启动日志里看到这一串写。

### 3.2 ICW1 的副作用

第 9–10 页列出 ICW1 的 a–f 六条副作用：

```c
static void write_icw1(struct pic8259 *c, uint8_t val)
{
    c->imr = 0;                 /* b. IMR 清零 */
    c->armed = ~c->line;        /* a. 边沿检测重置 */
    c->priority_add = 0;        /* c. IR7 最低优先级 */
    c->special_mask = false;    /* d. 清特殊屏蔽 */
    c->read_isr = false;        /* e. 选中读 IRR */
    c->poll = false;
    c->rotate_on_aeoi = false;
    c->single = val & 0x02;
    c->need_icw4 = val & 0x01;
    if (!c->need_icw4) {        /* f. IC4=0 时 ICW4 的功能清零 */
        c->auto_eoi = false;
        c->sfnm = false;
    }
    c->init_state = 1;
}
```

两条容易写错：

- **“边沿检测重置”不是清零。** 手册的意思是此刻为高的 IR 要先落下再升起才算请求。所以 `armed` 只留下当前为低的引脚（`~c->line`），而不是全部武装或全部解除。变异体 `pic-icw1-keeps-armed` 被 `test_edge_rules` 的“ICW1 之后已经为高的线必须落下再升起”挡下。
- **ICW1 不清 ISR。** 直觉上“初始化”就是全部清零，但图 9 里 ICW1 驱动的 master clear 信号只接 mask latch 和 edge sense latch，不接 in-service latch。变异体 `pic-icw1-clears-isr` 被挡下。

ICW 里有几位被有意忽略，理由各不相同：LTIM 被 PIIX4 禁用、由 ELCR 取代；ADI 只影响 MCS-80 模式的 CALL 地址；ICW4 的 μPM 选 INTA 格式，x86 CPU 只发 8086 格式的两个 INTA；BUF 和 M/S 控制 SP/EN 引脚和总线缓冲器，虚拟平台上没有这两样东西。

## 四、OCW：屏蔽、EOI、读状态

### 4.1 OCW2：EOI 的八种编码

OCW2 的 bit 7:5 是 R、SL、EOI 三位，八种组合（图 8，PIIX4 4.2.2.7 有同一张表）：

| R SL EOI | 含义 | Linux 用不用 |
|---|---|---|
| 0 0 1 | 非特定 EOI：清掉优先级最高的 ISR 位 | |
| 0 1 1 | 特定 EOI：清掉 bit 2:0 指定的 ISR 位 | `mask_and_ack_8259A` 用这个（`0x60 + irq`） |
| 1 0 1 | 非特定 EOI 并轮转 | |
| 1 1 1 | 特定 EOI 并轮转 | |
| 1 1 0 | 设置最低优先级（只轮转） | |
| 1 0 0 / 0 0 0 | AEOI 模式下轮转开 / 关 | |
| 0 1 0 | 无操作 | |

Linux 对一个 PIC 中断的处理是“先屏蔽、立刻 EOI、处理完再解除屏蔽”：

```c
/* arch/x86/kernel/i8259.c mask_and_ack_8259A */
    if (irq & 8) {
        inb(PIC_SLAVE_IMR);
        outb(cached_slave_mask, PIC_SLAVE_IMR);
        outb(0x60+(irq&7), PIC_SLAVE_CMD);         /* 'Specific EOI' to slave */
        outb(0x60+PIC_CASCADE_IR, PIC_MASTER_CMD); /* 'Specific EOI' to master-IRQ2 */
    } else {
        inb(PIC_MASTER_IMR);
        outb(cached_master_mask, PIC_MASTER_IMR);
        outb(0x60+irq, PIC_MASTER_CMD);            /* 'Specific EOI to master */
    }
```

这个“每个 tick 屏蔽一次、解除一次”的习惯会在 P4 的补发策略里产生一个反直觉的后果。

### 4.2 OCW3：读哪个寄存器、轮询、特殊屏蔽

OCW3 有三组功能：RR/RIS 选下一次读命令端口读 IRR 还是 ISR；P 位让下一次读命令端口变成一次“软件 INTA”（轮询）；ESMM/SMM 开关特殊屏蔽模式。几个规则来自手册的细节：RR=0 时 RIS 不改变选择；ESMM=0 时 SMM 不起作用；轮询只作用于被读的那一片，软件轮询级联系统时自己再去读从片（第 16 页）。轮询是一次性的，读过一次就恢复普通的读寄存器（变异体 `pic-poll-sticky`）。

特殊屏蔽模式（第 15 页）是为一种中断处理程序准备的：它想在处理自己的时候放行更低优先级的中断。正常模式下，ISR 里的位会挡住同级和更低级的请求；特殊屏蔽模式下，被 IMR 屏蔽的那个在服务级别不再挡别人。在这个模式下非特定 EOI 也不会清掉被屏蔽的在服务位（第 15 页 End of Interrupt 一节的最后一段，变异体 `pic-smm-eoi-clears-masked`）。

## 五、优先级判决

一片 8259A 此刻要不要拉高 INT、拉高的话为哪个 IR，是整个模型的核心：

```c
static int get_irq(const struct pic8259 *c)
{
    uint8_t pending = irr(c) & ~c->imr;
    uint8_t in_service = c->isr;
    int req, svc;

    if (!pending)
        return -1;
    req = highest(c, pending);
    if (c->special_mask)
        in_service &= ~c->imr;          /* 被屏蔽的在服务级别不挡人 */
    if (!c->is_slave && c->sfnm)
        in_service &= ~c->icw3;         /* 特殊全嵌套：接从片的 IR 不挡自己 */
    svc = highest(c, in_service);
    if (svc >= 0 && prio(c, req) >= prio(c, svc))
        return -1;
    return req;
}
```

IMR 在这里才起作用：它挡的是“送不送到 INT”，不是“IRR 置不置位”（第一章的冲突）。优先级用 `priority_add`（当前最高优先级的 IR 号）表示，轮转只改它，`prio()` 把 IR 号换算成 0 最高的优先级。

特殊全嵌套模式（SFNM，第 18 页）只对主片有意义：从片上 IRQ12 正在服务时，主片的 IR2 在 ISR 里，正常模式下从片上更高优先级的 IRQ9 会被主片的 IR2 挡住。SFNM 让主片不拿接从片的 IR 挡自己，于是 IRQ9 能嵌套进来。Linux 不用 SFNM，实现它是为了模型完整，`test_sfnm` 和变异体 `pic-sfnm-ignored` 守着它。

## 六、级联和 INTA

### 6.1 从片的 INT 就是主片的 IR2

```c
static void update(struct i8259 *p)
{
    struct pic8259 *m = &p->chip[0], *s = &p->chip[1];
    bool out;

    set_line(m, I8259_CASCADE_IR, get_irq(s) >= 0);
    out = get_irq(m) >= 0;
    if (out != p->int_out) {
        p->int_out = out;
        if (p->ops && p->ops->int_changed)
            p->ops->int_changed(p->opaque, out);
    }
}
```

每次可能改变状态的操作（写端口、线电平变化、INTA）之后都调 `update`：先按从片的判决驱动主片 IR2，再按主片的判决决定 INT，INT 变化时通过回调告诉主板（P1 2.4 节，主板据此踢 vCPU 0）。主片 IR2 对外部设备不可见，`i8259_set_irq(p, 2, ...)` 被忽略，因为那根线归从片驱动。

### 6.2 INTA：两个脉冲合成一步

8086 模式下 CPU 发两个 INTA 脉冲，主片在第一个脉冲置 ISR，向量在第二个脉冲交出；如果赢得判决的 IR 接了从片（ICW3 对应位为 1），向量由从片交出，从片在第二个脉冲置自己的 ISR。虚拟化下不存在两个分开的总线周期，`i8259_inta` 一步做完：

```c
uint8_t i8259_inta(struct i8259 *p)
{
    int irq = get_irq(m), irq2;

    if (irq < 0) {                      /* 伪中断：IR7，不置 ISR */
        p->spurious[0]++;
        vec = m->vector_base | 7;
    } else {
        ack(m, irq);
        if (!m->single && (m->icw3 & (1u << irq))) {
            irq2 = get_irq(s);          /* 级联：从片交出向量 */
            ...
        } else {
            vec = m->vector_base | irq;
        }
    }
    update(p);
    return vec;
}
```

主片是否把 IR2 当成级联口，看的是 ICW3 而不是固定接线：ICW3 没有置 bit 2 时，主片自己回答 IR2（`test_cascade` 的第二个用例，变异体 `pic-cascade-ignores-icw3`）。

### 6.3 AEOI

ICW4 的 AEOI 位让芯片在 INTA 最后一个脉冲的末尾自动做一次非特定 EOI。清掉的必然是刚置上的那一位，因为它刚刚赢得了优先级判决，于是 AEOI 下 ISR 永远是空的。

这个模式不是摆设。Linux 默认启动走 IOAPIC，但 `check_timer()` 在设置时钟时会把主片重新初始化成 AEOI（`legacy_pic->init(1)`，注释说是为了在 virtual wire 模式下不用手工确认时钟中断）。所以一次普通的 IOAPIC 启动里，PIC 虽然被屏蔽，处在的却是 AEOI 模式。P4 的补发策略要靠“IRQ0 的 ISR 位被清掉”判断 tick 被确认了，AEOI 下 ISR 根本不会置位，主板在 INTA 时单独处理这种情况（`split_irqchip_pre_run` 里比较 `acked[0]` 前后的变化）。

## 七、ELCR

ELCR1（`0x4D0`）、ELCR2（`0x4D1`）每一位对应一根 IRQ，1 = 电平触发（PIIX4 4.2.2.9/10）。IRQ0、1、2、8、13 固定是边沿（时钟、键盘、级联、RTC、FPU 错误），对应位保留：

```c
#define ELCR1_MASK  0xF8
#define ELCR2_MASK  0xDE
```

Linux 写 ELCR 的地方在 `arch/x86/kernel/acpi/boot.c`：`acpi_pic_sci_set_trigger` 按 FADT/MADT 给出的 SCI 触发方式设置 SCI 那一位，`acpi_register_gsi_pic` 在 PIC 模式下把 `_PRT` 描述为电平触发的 PCI 中断设成电平。mini-vmm 的 PCI INTx 在 IOAPIC 上走 16–23，PIC 只接 0–15，所以现有 guest 在 PIC 模式下的 ELCR 设置只涉及 SCI。

## 八、接到 KVM 上：`noapic` 启动和一个脉冲的形状

### 8.1 怎样让 guest 用 PIC

Linux 默认用 IOAPIC，PIC 被初始化后一直屏蔽。启动参数 `noapic` 让 Linux 不用 IOAPIC，所有 ISA 中断经 PIC、ExtINT、`KVM_INTERRUPT` 送到 vCPU 0：

```text
           CPU0
  0:        ...    XT-PIC      timer
  4:        ...    XT-PIC      ttyS0
```

`info irqchip` 里 `pic acked` 的 IRQ0 和 IRQ4 涨起来，`extint injected` 大于 0。split-irqchip 套件的 noapic 用例在两种模式下都检查 `XT-PIC` 的 timer 和 ttyS0 行，split 模式下另外要求 `extint injected` 大于 0。

### 8.2 IRQ0 的脉冲必须先低后高

这个用例第一次在 split 模式下跑的时候，guest 在串口驱动初始化时卡住。证据：

- `info irqchip`：`pic acked` 全是 0，`extint injected` 是 0，PIT 的 `ticks` 在涨，补发积压 `backlog` 一直增长；
- guest 日志里有 `APIC timer disabled due to verification failure`：Linux 用 PIT 的 jiffies 校验 LAPIC 定时器，jiffies 不动，校验失败。

PIT 在走，中断却一次都没交给 CPU。当时 IRQ0 的 tick 照搬 KVM 内核 PIT 的做法，在线上先拉高再拉低（KVM `i8254.c` 的 `pit_do_work` 里是 `kvm_set_irq(..., 1)` 紧跟 `kvm_set_irq(..., 0)`）。KVM 的内核 PIC 在边沿模式下把 IRR 锁住，线放低也不清，所以这样做没问题。可 2.1 节讲过，真实的 8259A 是透明锁存器：线一放低，IRR 就跟着消失，PIC 还没来得及被 INTA，请求就没了。INT 拉高又落下，`pic_int` 回到 0，vCPU 0 看到时已经无事可做。

改成先拉低再拉高、之后保持高电平：

```c
static void pit_pulse(struct split_irqchip *s)
{
    s->pit_irqs++;
    set_line_locked(s, 0, 0);
    set_line_locked(s, 0, 1);
}
```

这正是 mode 2 下 OUT0 的真实形状：大部分时间是高，每个周期只低一个时钟（P4）。IOAPIC 的边沿引脚只认 0→1，两种形状对它一样，所以默认的 IOAPIC 启动发现不了这个问题，只有 `noapic` 用例能。变异体 `irq0-pulse-ends-low` 把顺序改回去，被这个用例挡下。

这件事说明的是：照搬另一个实现的做法之前，要先确认它依赖的前提在自己这边是否成立。KVM 的 PIC 模型和真实芯片在“边沿模式下 IRR 是否锁存”这一点上不同，KVM 的 PIT 是配合它自己的 PIC 写的。

## 九、最难或最反直觉的地方

**IRR 是组合逻辑，不是寄存器。** 手册的正文把 IRR 叫寄存器，只有图 9 揭示它是一个透明锁存器的输出。从这一点能推出“边沿请求在 INTA 前落下会消失”“ICW1 后高着的线不算请求”“IRQ0 的脉冲必须先低后高”三条行为，它们在正文里分散在不同的地方，或者根本没写。

**两份手册冲突。** 判断依据是真实软件的依赖：Linux 的 `startup_ioapic_irq` 只有在 IMR 不挡 IRR 时才有意义。

**PIC 被屏蔽不等于不重要。** 默认启动里 PIC 处在 AEOI 模式、全部屏蔽，但它的 IMR 和 ISR 仍然是 P4 补发策略的输入。

## 十一、限制

- 8086 模式之外的 INTA 格式（MCS-80 的 CALL 指令）、缓冲模式、SP/EN 引脚不模拟，理由见 3.2 节。
- ExtINT 只送 vCPU 0（P1 第八章）。
- ELCR 的设置只影响 PIC。IOAPIC 的触发模式由 RTE 决定，和 ELCR 无关，这和真实 PIIX4 一致。
