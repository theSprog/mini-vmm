到上一篇为止，让 mini-vmm 里的 guest 关机只有两条路：在 guest 里敲 `poweroff`，或者在 host 上杀掉 VMM 进程。前一条要有人登进 guest，后一条相当于拔电源，文件系统没卸载、日志没落盘，下次启动 Arch 还要 fsck。真机上还有第三条路：按一下机箱上的电源键，操作系统收到通知，自己走完关机流程。云平台的“关闭实例”、QEMU 的 `system_powerdown`、libvirt 的 `virsh shutdown`，用的都是这第三条路。

这一篇讲这第三条路在 ACPI 里是怎么定义的：硬件用什么方式通知操作系统“有事发生”，操作系统怎么找到是哪件事、怎么确认处理完了，Linux 又怎么把一次按键一路传到 systemd。下一篇《实现篇》再讲 mini-vmm 怎么模拟这块硬件。ACPI 表的基本结构（RSDP、FADT、MADT、DSDT 和 `\_S5`）在《固件与启动协议·原理篇》第 1.4 节讲过，这里直接用。

本文的章节号都指 ACPI 6.5（`ref/ACPI_Spec_6_5_Aug29.pdf`）。

## 一、问题：硬件怎么“请”操作系统做一件事

关机这件事本身，guest 早就会做：《固件与启动协议·原理篇》1.4.5 节讲过，Linux 关机的最后一步是执行 DSDT 里的 `\_S5`，往 `PM1a_CNT` 写 `SLP_TYP=5 | SLP_EN`，VMM 收到这次端口写就退出。缺的是反方向：**由平台发起，请操作系统去关机**。

这个方向有两个要求。第一，平台不能替操作系统做决定：桌面系统按电源键可能是关机，可能是休眠，可能弹一个对话框，也可能被正在刻光盘的程序拦下来，这是操作系统的策略。平台只负责说“电源键被按了”。第二，通知不能丢：操作系统可能正忙，可能暂时关了中断，可能还没加载按钮驱动，事件要一直挂在那里，直到操作系统明确说“我看到了”。

ACPI 用一对寄存器位加一根中断线满足这两点：

```text
                     ┌────────── 平台（mini-vmm）──────────┐
 按下电源键 ──────►  │  PM1_STS.PWRBTN_STS = 1（锁存）      │
                     │            │                         │
                     │            ▼                         │
 OSPM 写 PM1_EN ──►  │  PWRBTN_EN ── AND ──► SCI 线（电平）│──► IOAPIC 引脚 9 ──► CPU
                     └──────────────────────────────────────┘
 OSPM 处理完，往 PM1_STS 的 bit 8 写 1 ──► 状态位清零 ──► SCI 落下
```

**状态位**记录“事件发生过”，只由硬件置位，软件只能写 1 把它清掉（write-1-to-clear，下文简称 W1C）。**使能位**由操作系统设置，表示“这个事件我要处理”。两者同时为 1 时，**SCI**（System Control Interrupt）有效。

规范对这件事的原话（4.8.3.1.1，Table 4.11 的 PWRBTN_STS）是 “while PWRBTN_EN and PWRBTN_STS are both set, an interrupt event is raised”。注意是 **while**：SCI 是一个持续的电平，不是一次性的脉冲。它直接带来三个推论，下一篇的实现和测试都建立在它们上面：

1. **先按键、后使能也会触发。** 操作系统启动早期还没打开 `PWRBTN_EN` 时按下的键，状态位一直锁存着，使能位一写上，SCI 马上有效。事件不丢。
2. **不清状态位，SCI 就一直有效。** 电平触发的中断在 EOI 之后如果线还是高的，会立刻再来一次。操作系统不处理，就会被反复打断，所以它必须处理。
3. **清掉状态位或关掉使能位，SCI 就落下。** 操作系统用 W1C 表达“我看到了”，平台不需要另外的确认协议。

W1C 本身也有讲究：为什么不是“写 0 清零”？因为一个状态寄存器里有多个事件位（定时器溢出、总线主控、全局锁、电源键、睡眠键、RTC 闹钟……）。如果写 0 清零，操作系统想清电源键那一位，就得先读出整个寄存器、改一位、再写回去，而在读和写之间硬件可能又置上了别的位，写回时被一起清掉，那个事件就丢了。W1C 下写 `0x0100` 只清 bit 8，其余位写的是 0，不受影响。

## 二、固定事件和通用事件

ACPI 把“平台要通知操作系统的事”分成两类。

**固定事件（fixed events）**：每台 ACPI 机器都可能有、位置由规范定死的一小组事件，状态位和使能位在 PM1 事件寄存器块里（4.8.1.1、Table 4.11/4.12）：

| bit | 事件 | 说明 |
|---|---|---|
| 0 | TMR | PM 定时器的最高位翻转 |
| 4 | BM | 总线主控请求（只有状态位） |
| 5 | GBL | 固件释放了全局锁 |
| 8 | PWRBTN | 固定功能电源按钮 |
| 9 | SLPBTN | 固定功能睡眠按钮 |
| 10 | RTC | RTC 闹钟 |
| 14 | PCIEXP_WAKE | PCIe 唤醒（只有状态位，“使能”的含义是反的） |
| 15 | WAK | 系统已从睡眠中醒来（只有状态位） |

PM1 事件块的前一半是状态寄存器 `PM1_STS`，后一半是使能寄存器 `PM1_EN`，两者一样宽，各占 `PM1_EVT_LEN / 2` 字节（4.8.1.1）。FADT 里写着块的端口地址和长度。

**通用事件（General-Purpose Events，GPE）**：平台自定义的事件，状态和使能位在 GPE 寄存器块里，事件号的含义由 DSDT 里的 AML（`_Lxx`/`_Exx` 方法）解释。CPU 热插拔、内存热插拔、PCI 热插拔、笔记本的盖子和电池，都走 GPE。它要一个 AML 解释器跑起来、平台写对一段 AML 才能工作，比固定事件多出一整层。

两类事件共用同一根 SCI 线。操作系统收到 SCI 时并不知道是谁，要把固定事件和 GPE 的状态位都扫一遍。

### 2.1 电源按钮的两种形态

电源按钮恰好两种形态都可以有（4.8.2.2.1，Table 4.8）：

- **固定功能按钮**：FADT `Flags` 的 `PWR_BUTTON`（bit 4）为 **0**，命名空间里没有电源按钮设备对象。按键直接置 `PWRBTN_STS`。
- **控制方法按钮**：`PWR_BUTTON` 为 1，DSDT 里有一个 `PNP0C0C` 设备，按键产生一个 GPE，GPE 的 AML 方法再对这个设备执行 `Notify(PWRB, 0x80)`。

Table 5.10 对 `PWR_BUTTON` 的说明是 “A zero indicates the power button is handled as a fixed feature programming model; a one indicates the power button is handled as a control method device”。这个位的取值很容易记反：**0 才表示“有固定按钮”**。mini-vmm 以前一直把它置 1（含义是“按钮是控制方法设备”，可 DSDT 里并没有这个设备，等于说“没有电源按钮”），这一个里程碑把它清成 0。

mini-vmm 选固定功能按钮：不需要 GPE 块、不需要写 AML，整条链路只有 PM1 的两个寄存器和一根中断线，适合第一次把“平台事件”这个机制讲清楚。GPE 留给 cpu-hotplug 里程碑，那时候设备通知非走 AML 不可。

### 2.2 ACPI 模式和 SCI_EN

`PM1_CNT` 的 bit 0 是 `SCI_EN`（Table 4.13）。它的含义是“电源管理事件现在送 SCI 还是送 SMI”：传统 PC 开机时处在“传统模式”，这些事件交给 BIOS 的 SMM 代码处理；操作系统要接管时，往 FADT 的 `SMI_CMD` 端口写 `ACPI_ENABLE`，固件把 `SCI_EN` 置 1。这个位由硬件维护，软件写不动。

FADT 的 `SMI_CMD` 为 0 表示平台没有 SMI 命令端口，一上电就是 ACPI 模式，`SCI_EN` 恒为 1。mini-vmm 没有 SMM，正是这种情况。

### 2.3 使能位读得回来，才算有这个事件

FADT 里没有一张“这台机器实现了哪些固定事件”的清单。规范的办法是 4.8.3.1 的一句话：寄存器块里没实现的位读回 0、写入无效。ACPICA 就靠它探测：`acpi_enable_event()`（`drivers/acpi/acpica/evxfevnt.c`）写完使能位会再读一遍，读回来不是 1，就打印 `Could not enable <事件名> event`，返回 `AE_NO_HARDWARE_RESPONSE`，调用方把这个事件当作不存在。

Linux 启动时有两处会这样探测：

- **全局锁（GBL）。** 全局锁是操作系统和固件（SMM 里的代码）共用一个硬件资源（典型的是嵌入式控制器）时的互斥锁。锁字本身在 FACS（Firmware ACPI Control Structure，5.2.10）里，一块由固件预留、FADT 的 `FIRMWARE_CTRL` 指过去的内存；双方用原子的比较交换抢锁，抢不到的一方在锁字里置“等待”位，持有方释放时通知对方：固件释放时置 `GBL_STS` 发 SCI，操作系统释放时写 `PM1_CNT.GBL_RLS` 发 SMI。ACPICA 初始化时为 `GBL` 事件装处理函数（`acpi_ev_init_global_lock_handler()`，`evglock.c`），`GBL_EN` 写不进去，它就打印 `No response from Global Lock hardware, disabling lock`，此后 AML 里要用全局锁都会失败。
- **RTC 闹钟（RTC）。** `RTC_STS`/`RTC_EN` 让操作系统知道是 RTC 闹钟把机器从睡眠里叫醒的。这对位是可选的（4.8.2.4），但实现了就必须在闹钟响时置 `RTC_STS`。`rtc-cmos` 驱动加载时为它装处理函数。

5.2.10 第一段写明，FACS 只有硬件精简平台可以不提供。mini-vmm 不是硬件精简平台，所以给出 FACS 并让 `GBL_EN` 写得进去；这台机器没有会持有全局锁的固件，`GBL_STS` 永远不会置位，锁实际上只有操作系统一方在用，这是如实的描述。RTC 唤醒只对睡眠状态有意义，mini-vmm 只支持 S5，这对位不实现，guest 每次启动会打印一次 `ACPI Error: Could not enable RealTimeClock event`，这是规范允许的平台配置得到的预期结果。

## 三、SCI 是一根什么样的中断线

FADT 的 `SCI_INT`（5.2.9，Table 5.9，偏移 46）写着 SCI 接在哪个中断上，传统上是 9。同一格里还有一句要求：“OSPM is required to treat the ACPI SCI interrupt as a shareable, level, active low interrupt”。

**电平触发**是第一章三个推论的硬件前提：状态位锁存多久，线就有效多久。如果按边沿处理，操作系统在 EOI 之前状态位又被置了一次（第二次按键），这次不会产生新的边沿，事件就挂在状态寄存器里没人知道，直到下一个别的 SCI 碰巧来扫一遍。**可共享**是因为固定事件、GPE、有些平台上的其他设备都挂在这根线上。

ISA 中断号 9 到 IOAPIC 引脚 9 是恒等映射。按 5.2.12.5，MADT 里的 Interrupt Source Override（ISO）只在两种情况下需要：ISA 中断号和 GSI 不相等，或者极性、触发方式和总线的标准不同。SCI 有它自己的“标准”，就是上面那句 shareable、level、active low；Linux 的 `acpi_sci_ioapic_setup()`（`arch/x86/kernel/acpi/boot.c`）在没有 ISO 时就把 SCI 配成电平、低有效。所以 mini-vmm 不给 SCI 写 ISO，guest 自然按规范的默认值配置引脚。

MP table 也描述 IRQ 9（《固件与启动协议·原理篇》1.3 节），它的中断项同样有极性和触发方式（MPS 1.4 Table 4-10，ACPI 5.2.12.5 的 Table 5.26 与之相同）。Linux 有 ACPI 时不看 MP table，但两份表说法不一样时，只用 MP table 的系统（`acpi=off` 或别的操作系统）会把 SCI 引脚配成边沿。mini-vmm 让 MP table 的 IRQ 9 也写成电平、低有效，两份表保持一致。

“低有效”在虚拟化里还有一层含义：引脚上的物理电平是低，可 VMM 调 KVM 的 `KVM_IRQ_LINE` 时传的是“有效 = 1”。KVM 的 IOAPIC 不看重定向表里的极性位，PCI INTx（同样声明为低有效）也是这个约定。电平极性是 guest 对引脚的配置，VMM 这边只说“有效”或“无效”。

## 四、Linux 怎么接住这次按键

下面是 Linux 7.4-rc2 里一次按键从 SCI 到用户态的完整路径。

```text
IOAPIC 引脚 9 ──► CPU 中断
  acpi_irq()                                  drivers/acpi/osl.c，request_irq(..., IRQF_SHARED, "acpi")
    acpi_ev_sci_xrupt_handler()               drivers/acpi/acpica/evsci.c
      acpi_ev_fixed_event_detect()            drivers/acpi/acpica/evevent.c
        读 PM1_STS、读 PM1_EN
        对每个固定事件：STS 和 EN 都置位？
          acpi_ev_fixed_event_dispatch()
            先往 PM1_STS 写 1 清状态位   ◄── 此刻 SCI 落下
            调用安装的处理函数
              acpi_button_event()             drivers/acpi/button.c
                acpi_os_execute(OSL_NOTIFY_HANDLER, ...)  推迟到工作队列
      acpi_ev_gpe_detect()                    （没有 GPE 块，什么都不做）
  EOI ──► IOAPIC：线已经无效，不再触发

工作队列：
  acpi_button_notify_run()
    acpi_button_notify()
      input_report_key(KEY_POWER, 1); input_sync()
      input_report_key(KEY_POWER, 0); input_sync()
      acpi_bus_generate_netlink_event()
        ──► /dev/input/eventN（evdev）
              systemd-logind：HandlePowerKey=poweroff（logind.conf(5) 的默认值）
                systemctl poweroff ──► 停服务、卸载文件系统
                  reboot(LINUX_REBOOT_CMD_POWER_OFF)
                    acpi_power_off() ──► \_S5 ──► 写 PM1_CNT = SLP_TYP 5 | SLP_EN
```

几个值得注意的地方：

- **清状态位在调用处理函数之前**（`acpi_ev_fixed_event_dispatch()` 的第一句）。处理函数执行期间再按一次键，状态位会被重新置上，EOI 之后电平仍然有效，中断再来一次，不会丢。这正是电平触发配合 W1C 的用法。
- **中断上下文里只报一个“按了”**。按钮驱动的固定事件处理函数 `acpi_button_event()` 把真正的工作推到 `kacpi_notify` 工作队列，由它向 input 子系统报一对按下、松开事件。所以 guest 用户态从 `/dev/input/eventN` 读到的是两个 `EV_KEY`：`code 116（KEY_POWER）value 1`，然后 `value 0`。
- **按钮设备是谁建的。** `PWR_BUTTON` 为 0 时，ACPI 扫描代码（`drivers/acpi/scan.c` 的 `acpi_bus_scan_fixed()`）在命名空间之外加一个 `LNXPWRBN` 设备，按钮驱动绑定它，再用 `acpi_install_fixed_event_handler(ACPI_EVENT_POWER_BUTTON, ...)` 装处理函数。装处理函数时 ACPICA 打开 `PWRBTN_EN`，再加上 2.3 节的全局锁使能位，guest 启动完成后 `PM1_EN` 读回来是 `0x0120`。
- **计数器。** ACPICA 给每个固定事件记一个计数，`/sys/firmware/acpi/interrupts/ff_pwr_btn` 是电源键的，`/sys/firmware/acpi/interrupts/sci` 是 SCI 总数。它们是从 guest 里观察“按了几次、SCI 来了几次”的直接手段，下一篇的测试就靠它们。

用户态这一段对 VMM 是透明的：BusyBox 的 initramfs 里没有人打开 `/dev/input/event0`，按键事件进了 evdev 就没有下文；Arch 里 logind 打开了所有带 `KEY_POWER` 的输入设备，按下就关机。不管哪种，平台这边的行为一样：置状态位、拉 SCI、等 W1C。

## 五、小结

- 平台要“请”操作系统做事，用的是状态位、使能位和 SCI：状态位由硬件置、软件写 1 清；两者都置位时 SCI 有效；SCI 是电平，状态位不清就一直有效，事件因此不会丢。
- 事件分固定事件（PM1 块里规范定死的位）和 GPE（平台自定义、靠 AML 解释）。电源按钮可以是固定功能按钮（FADT `PWR_BUTTON` = 0）或控制方法设备，mini-vmm 用前者。
- 没实现的位读回 0，ACPICA 靠写使能位再读回来探测固定事件。全局锁要 FACS 加上写得进去的 `GBL_EN`；RTC 唤醒是可选的。
- SCI 按规范是可共享、电平、低有效，恒等映射到 GSI 9，不需要 MADT ISO；MP table 也要写成同样的属性。
- Linux 在中断里读 STS 和 EN、先清状态位再调处理函数，按钮驱动在工作队列里报一对 `KEY_POWER`，systemd-logind 据此关机，最后又回到 `\_S5` 和 `PM1_CNT`。

下一篇《实现篇》讲 mini-vmm 怎么把这些寄存器、这根线和 monitor 的 `system_powerdown` 接起来，以及怎么证明它们是对的。
