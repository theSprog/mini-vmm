《原理篇》讲了平台怎么用状态位、使能位和 SCI 请操作系统做事，Linux 又怎么把一次按键传到 systemd。这一篇讲 mini-vmm 这边：PM1 寄存器怎么模拟，SCI 怎么接到中断控制器，ACPI 表要改哪几处，monitor 的 `system_powerdown` 做了什么，以及怎么证明这些都是对的。

## 一、三层：寄存器、接线、表

```text
monitor（I/O 线程）           vCPU 线程（PIO exit）
   system_powerdown              in/out 0x600-0x607
          │                              │
          └──────────┬───────────────────┘
                     ▼  持 vm->io_lock
   src/power.c           接线：PIO 注册、SCI → GSI 9、复位回调、monitor 命令、S5 → 退出
                     │
                     ▼
   src/devices/acpi_pm.c 寄存器语义：STS/EN/CNT/SLEEP_*，算出 SCI 电平，报告 S5 请求
                     │ set_sci(level)
                     ▼
   irqchip_set_irq(vm, 9, level)   内核 irqchip：KVM_IRQ_LINE；split：用户态 IOAPIC

   src/boot/acpi.c、mptable.c      表：FADT（PWR_BUTTON=0、FIRMWARE_CTRL）、FACS、MP 表 IRQ 9
```

`acpi_pm.c` 只认识寄存器，不认识 VM：SCI 经回调送出去，S5 请求作为返回值交给调用方。这样单元测试不需要 KVM，喂一串读写、看回调记录就能判定。`power.c` 把它挂到总线上。这一层次和 split irqchip 的三个芯片（芯片模型与主板接线分开）是同一种做法。

所有入口都在 `vm->io_lock` 下：PIO 回调由 exit 分发路径持锁调用，monitor 命令在 I/O 线程上自己拿锁，复位回调由 `vm_reset` 持锁调用。monitor 按键和 guest 的 W1C 写可能同时发生，锁保证它们对 `sts` 的修改和 SCI 的重新计算是一个整体。

## 二、寄存器模型

### 2.1 SCI 是算出来的

```c
static void update_sci(struct acpi_pm *pm)
{
    bool level = (pm->sts & pm->en) != 0;

    if (level == pm->sci)
        return;
    pm->sci = level;
    if (level)
        pm->sci_raises++;
    if (pm->set_sci)
        pm->set_sci(pm->opaque, level);
}
```

每次按键、每次 guest 写 STS 或 EN、每次复位之后都调它。SCI 不是“按键时发一次中断”，而是 `STS & EN` 这个表达式的当前值。《原理篇》第一章的三个推论都直接落在这一行上：先按后使能，写 EN 时表达式变 1；不清状态位，表达式一直是 1；W1C 或关使能，表达式变 0。

只在电平变化时调回调：irqchip 收到的永远是交替的 1、0，不会出现连续两个 1。对内核 irqchip 来说重复的 `KVM_IRQ_LINE 1` 无害，但用户态 IOAPIC 的电平处理（《split irqchip P2》）按“线的状态”而不是“调用次数”工作，交替的调用让两边的状态始终一致，也让 `sci_raises` 成为一个有意义的计数：SCI 真正被拉起的次数。

### 2.2 W1C 和字节访问

```c
for (i = 0; i < size && off + i < ACPI_PM_REG_LEN; i++) {
    uint32_t o = off + i;
    uint16_t b = (uint16_t)((val >> (8 * i)) & 0xFF);
    unsigned int sh = 8 * (o & 1);

    switch (o) {
    case ACPI_PM_OFF_STS:
    case ACPI_PM_OFF_STS + 1:
        pm->sts &= (uint16_t)~(b << sh);          /* 写 1 清零 */
        break;
    case ACPI_PM_OFF_EN:
    case ACPI_PM_OFF_EN + 1:
        pm->en = (uint16_t)((pm->en & ~(0xFFu << sh)) | (b << sh));
        pm->en &= PM1_EN_IMPL;                    /* 没实现的位写不进去 */
        break;
    ...
```

写操作按字节拆开。规范要求 PM1 的三个寄存器都接受字节和字访问（Table 4.11-4.13 的说明），所以 guest 单独写 `0x603`（EN 的高字节）也必须生效，单独写 `0x600`（STS 的低字节）不能碰到 bit 8。Linux 总是按 `PM1_EVT_LEN / 2 = 2` 字节访问，字节访问的错误在 Linux guest 上永远看不出来，只能由单元测试挡住（2.6 节）。读也一样，先把寄存器文件拼成 8 个字节的镜像，再按偏移和宽度取，一次 4 字节读跨过 STS 和 EN 也能得到小端拼接的结果。

### 2.3 实现了哪些位

```c
#define PM1_STS_IMPL  ACPI_PM1_PWRBTN
#define PM1_EN_IMPL   (ACPI_PM1_PWRBTN | ACPI_PM1_GBL)
```

状态位只有 `PWRBTN_STS`，使能位多一个 `GBL_EN`。理由在《原理篇》2.3 节：ACPICA 写使能位再读回来，判断这个固定事件有没有硬件。`GBL_EN` 读不回来，ACPICA 就认为没有全局锁；mini-vmm 提供了 FACS（第四章），锁字是真的，所以 `GBL_EN` 必须写得进去。`GBL_STS` 只在固件释放了操作系统等着的锁时置位，这台机器没有会持有锁的固件，它就不实现，读回 0。

软件写 STS 永远只能清位，不能置位：`sts &= ~b` 这一行没有任何路径能让 `sts` 多出一位，只有 `acpi_pm_press_power_button()` 会置 `PWRBTN_STS`。

### 2.4 PM1_CNT

`PM1_CNT` 的 `SCI_EN`（bit 0）读回恒为 1：FADT 的 `SMI_CMD` 是 0，平台一上电就在 ACPI 模式（Table 4.13）。读出时由 `image()` 现场或上去，不存进 `cnt`，所以软件写 0 也清不掉。`GBL_RLS`（bit 2）和 `SLP_EN`（bit 13）只写、读回 0，bit 15:14 保留、读回 0，写入时都从 `cnt` 里去掉。

S5 请求有三种写法，都要识别：

| 写法 | 谁会这样写 |
|---|---|
| `PM1_CNT` 字写 `SLP_TYP=5 \| SLP_EN` | Linux `acpi_hw_legacy_sleep()`：先写一次只有 `SLP_TYP` 的值，再写带 `SLP_EN` 的值 |
| 只写 `PM1_CNT` 的高字节（`0x605`） | `SLP_TYP`（bit 12:10）和 `SLP_EN`（bit 13）都在高字节，字节访问的 OSPM 可以只写这一个字节 |
| `SLEEP_CONTROL` 寄存器（`0x606`）写 `SLP_TYP=5 \| SLP_EN` | 只支持硬件精简 ACPI 的内核（`acpi_hw_extended_sleep()`，见 `include/boot/acpi.h`） |

`SLP_EN` 置位而 `SLP_TYP` 不是 5 时返回 `ACPI_PM_SLEEP_IGNORED`，调用方打一条警告：DSDT 里只有 `\_S5`，guest 走到这里说明它没按 DSDT 办事。

## 三、接线

```c
static void set_sci(void *opaque, int level)
{
    struct vmm_vm *vm = opaque;

    if (irqchip_set_irq(vm, ACPI_SCI_IRQ, level) != VMM_OK)
        vmm_err("acpi: failed to set SCI (GSI %d) to %d", ACPI_SCI_IRQ, level);
}
```

`irqchip_set_irq()` 在内核 irqchip 下是 `KVM_IRQ_LINE`，在 split 下进用户态 IOAPIC 和 PIC 的 IRQ 9。传的是“有效 = 1”：KVM 和用户态 IOAPIC 都不看重定向表的极性位，guest 把引脚配成低有效只是它对这根线的描述（《原理篇》第三章）。

PM1 寄存器块注册成一个 8 字节的 PIO 设备 `acpi-pm1a`，覆盖 PM1a 事件块（`0x600`，4 字节）、控制块（`0x604`，2 字节）和两个扩展睡眠寄存器（`0x606`、`0x607`）。地址只在 `include/boot/acpi.h` 定义一次，FADT 和 PIO 注册都从那里取；`power.c` 开头有一组 `_Static_assert` 核对这些端口和寄存器文件里的偏移对得上，FADT 声明的端口和实际注册的不一致时编译就失败。

整机复位（《整机复位》）时，`power_reset()` 让寄存器回到上电值，`update_sci()` 顺带把挂着的 SCI 放下。

S5 时 `pm_write()` 返回 `VMM_ERR_EXIT`，vCPU 循环按退出码 0 退出 VMM。这一段在 linux-boot 里程碑就有，这次只是从 `acpi.c` 里搬进了 `power.c`。

## 四、ACPI 表的三处改动

**FADT `PWR_BUTTON` 清 0。** 这是“有固定功能电源按钮”的声明（Table 5.10）。以前置 1，Linux 不建 `LNXPWRBN`，PM1 里的电源按钮事件没人接。

**FACS。** 64 字节，放在 MADT 后面 64 字节对齐的位置，FADT 的 `FIRMWARE_CTRL` 和 `X_FIRMWARE_CTRL` 都指向它。全局锁字初值 0，版本 3，`flags` 为 0（没有 S4BIOS、没有 64 位唤醒环境，这台机器没有 S3/S4）。`hardware_signature` 取 FACS 之前全部表字节的 FNV-1a：规范要求 ACPI 表一变它就变（Table 5.13），操作系统靠它判断能不能从休眠镜像恢复。FACS 不能落在 E820 的 RAM 里（5.2.10），ACPI 表区 `[0xE0000, 0xF0000)` 本来就在 E820 的保留区里。FACS 最后填，这样签名覆盖的是已经定稿的表；FADT 的表头（校验和）要等知道 FACS 地址以后才填，所以挪到了 MADT 之后。

**MP table 的 IRQ 9。** 中断项的 `irqflag` 写成 `0x0F`（低有效、电平），和 FADT `SCI_INT` 的规定一致。MADT 不写 ISO：SCI 恒等映射，属性又正是 Linux 没有 ISO 时用的默认值（5.2.12.5）。

## 五、monitor 的 `system_powerdown`

```text
mon> system_powerdown
  power button pressed: PM1_STS=0x0100 PM1_EN=0x0120 SCI=1
  presses since reset: 1, SCI raised 1 times
OK
```

命令拿 `io_lock`，按一下按钮，在锁里取出寄存器和计数，放锁后回复。它不等 guest 关机：guest 怎么处理按键是 guest 的策略，BusyBox 里没人听按键，guest 照常运行；Arch 会关机，VMM 随后因 S5 退出，monitor 连接随之关闭。这和 QEMU 的同名命令一致。

回复里带上寄存器状态和两个计数，是为了“按了没反应”的时候能直接看出卡在哪一层：

- `PM1_EN` 的 bit 8 是 0：guest 没有打开电源按钮事件（ACPI 被禁用、按钮驱动没加载、FADT 声明错了）。这时回复多一行 `PWRBTN_EN is clear: the guest has not enabled the fixed power button, no SCI raised`。
- `SCI=1` 但 guest 里 `/proc/interrupts` 的 IRQ 9 不动：问题在中断路由。
- 第二次按键时 `SCI raised` 没有跟着加 1：上一次的状态位没被清掉，SCI 一直挂着（guest 的处理函数没跑完，或者 W1C 坏了）。

## 六、实际观察到的执行流

用 `--trace-pio` 跑一次 BusyBox guest（Linux 7.4-rc2，2 vCPU），按一次键再关机，PM1 块上的全部访问是 34 次。按时间分三段：

**启动时 ACPICA 初始化固定事件（约 0.69 s）**

```text
0602 R2 0000   0602 W2 0000     ×5   逐个关掉 5 个固定事件的使能位（TMR、GBL、PWRBTN、SLPBTN、RTC）
0600 W2 0020                         清 GBL_STS
0602 R2 0000   0602 W2 0020
0602 R2 0020                         读回：GBL_EN 写进去了，全局锁存在
0600 W2 0100                         清 PWRBTN_STS（按钮驱动装处理函数前）
0602 R2 0020   0602 W2 0120
0602 R2 0120                         读回：PWRBTN_EN 写进去了
0600 W2 0400                         rtc-cmos：清 RTC_STS
0602 R2 0120   0602 W2 0520
0602 R2 0120                         读回：RTC_EN 没写进去 → "Could not enable RealTimeClock event"
0600 W2 0400   0602 R2 0120   0602 W2 0120   0602 R2 0120   rtc-cmos 把 RTC 事件关回去
```

这一段就是《原理篇》2.3 节的探测过程。`GBL_EN` 和 `PWRBTN_EN` 读回 1，`RTC_EN` 读回 0，guest 日志里对应地只有 RTC 那一条 `ACPI Error`。

**按键**

```text
mon> system_powerdown                         VMM：PWRBTN_STS=1，SCI 0→1
0600 R2 0100                                  acpi_ev_fixed_event_detect()：读 STS
0602 R2 0120                                  读 EN；STS & EN 有 bit 8
0600 W2 0100                                  acpi_ev_fixed_event_dispatch()：W1C，SCI 1→0
```

三次访问前后共 93 µs，都在 SCI 的中断处理里完成。之后 guest 里 `evkey` 读到 `key 116 1`、`key 116 0`，`/proc/interrupts` 的 IRQ 9 从 0 变成 1，`ff_pwr_btn` 从 0 变成 1。

**关机**

```text
0600 W2 8000                                  清 WAK_STS
0600 W2 c731                                  acpi_hw_clear_acpi_status()：清全部固定事件状态位
0604 R2 0001                                  读 PM1_CNT：SCI_EN=1
0604 W2 1401                                  SLP_TYP=5
0604 W2 3401                                  SLP_TYP=5 | SLP_EN → VMM 退出
```

`0xc731` 是 ACPICA 的 `ACPI_BITMASK_ALL_FIXED_STATUS`，包括这台机器没有实现的 TMR、BM、GBL、SLPBTN、RTC、PCIEXP_WAKE 状态位，W1C 下写这些位没有副作用，正是 W1C 的设计目的。

Arch guest（Linux 7.2.11）上，systemd-logind 的日志是 `Watching system buttons on /dev/input/event0 (Power Button)`；按键后串口上依次出现 systemd 停各个 unit 的输出，guest uptime 从按键前的 8.58 s 到 `reboot: Power down` 的 10.37 s，约 1.8 s 走完正常关机，VMM 打印 `guest requested poweroff via ACPI S5 (port 0x604, value 0x3401)` 后以 0 退出。

## 七、最容易弄错的地方

**`PWR_BUTTON` 的取值是反的。** 0 表示“电源按钮是固定功能”，1 表示“是控制方法设备”。置 1 而 DSDT 里又没有 `PNP0C0C`，等于说没有电源按钮。表是静态的，Linux 不会报错，只是不建 `LNXPWRBN`，按键石沉大海。

**“没实现的位读回 0”不只是规范的整洁要求，它是 ACPICA 的探测手段。** 把 EN 做成“写什么存什么”，日志很干净，ACPICA 却以为平台有全局锁、有 RTC 唤醒；照规范只保留实现了的位，ACPICA 立刻发现这台机器缺 FACS。规范要求的东西缺了一块，诚实的寄存器会让它暴露出来，所以这次把 FACS 补上了。

**字节访问只有单测看得见。** 寄存器模型如果把每次访问都当成 2 字节，写 `0x603` 会被当成写 `0x602` 的低字节，Linux guest 永远不会这样访问，e2e 全绿。规范写明了字节访问，就只能在单元测试里按字节逐个断言。

**SCI 只在变化时通知。** 如果每次 `update_sci()` 都无条件调回调，guest 每读一次 STS 都会触发一次 `irqchip_set_irq(9, 1)`。对内核 irqchip 无害，对用户态 IOAPIC 也无害（它按电平工作），但 `sci_raises` 就失去了意义，monitor 的回复也就不能用来判断 SCI 是不是一直挂着。

## 八、验证

**单元测试** `acpi_pm_test`（54 checks / 11 cases）：判据逐条出自 ACPI 6.5 的 4.8.3.1 和 Table 4.11-4.13、4.19，期望值在用例里按位写出，不调用被测代码的宏去算。SCI 回调是一个记录器，记下调用次数和最后的电平，用来同时断言“只在变化时调用”和“最终电平”。`boot_tables_test` 加了 FADT `PWR_BUTTON`、FACS 的全部字段（包括独立算一遍 hardware signature）和 MP 表 IRQ 9 的 `irqflag`。

**e2e** `acpi-events` suite（4 个用例）：

- BusyBox guest，内核 irqchip 和 split irqchip 各一次。两种模式下 SCI 分别经 KVM 的 IOAPIC 和用户态 IOAPIC 送达，电平中断的确认路径（remote IRR、EOI）不同。guest 里先确认只有一个 `LNXPWRBN`、IRQ 9 是 `9-fasteoi acpi`、没有全局锁的报错，然后按两次键：每次 `evkey` 收到一对 `KEY_POWER`，SCI 中断计数和 `ff_pwr_btn` 正好加 1，monitor 报 `presses since reset: 2, SCI raised 2 times`。“正好加 1”挡住 W1C 失效：状态位清不掉时电平一直有效，计数一路涨上去。最后 `poweroff -f` 必须走到 S5。
- `acpi=off`：guest 不碰 PM1，按键只锁存状态位，回复说明 `PWRBTN_EN is clear`，SCI 不拉起，guest 照常回显。
- Arch guest：logind 在监听 Power Button，按键后正常关机，VMM 经 S5 以 0 退出。

guest 里接按键用的是新写的 `tools/guest/evkey.c`：按名字找到输入设备、打开之后 fork，父进程打印 `listening` 后返回，子进程在后台收满指定数目的 `EV_KEY`，写进一个命名管道。这样拆是为了让每一步都靠一个确定的信号衔接：shell 提示符出现时设备一定已经打开，host 再去按键，不会因为监听还没就位而丢事件；guest 里 `cat` 这个管道会阻塞到子进程写完为止，等的正是“事件收齐了”这件事本身，不需要猜按键多久能送到。

**对照**：`tests/mutate.py acpi-events` 的 16 个源码 mutant 全部变红。寄存器和表的 12 个由单测挡住（W1C 失效、写 1 反而置位、忽略使能位、高字节当低字节、未实现位写得进去、`GBL_EN` 写不进去、`SCI_EN` 读 0、复位不清、`PWR_BUTTON` 置位、FACS 没被引用、hardware signature 不覆盖全部表、MP 表 IRQ 9 写成边沿）；接线的 4 个各让 e2e 变红（SCI 接到 GSI 10、W1C 后 SCI 不落、monitor 绕过寄存器模型直接改 `sts`、S5 被忽略）。

## 九、限制

- **只有电源按钮一个事件。** 睡眠按钮、PM 定时器、RTC 唤醒都不实现；没有 GPE 块，所以也没有 `Notify`。设备通知（CPU、内存、PCI 热插拔）都要 GPE 和 AML，留给 cpu-hotplug 里程碑。
- **只有 S5。** DSDT 只声明 `\_S5`，S1-S4 的请求记一条警告后忽略，FACS 的唤醒向量从不使用。
- **e2e 分不出 SCI 是电平还是脉冲。** 两次按键之间 guest 早已处理完上一次中断，引脚上没有挂着的 remote IRR。电平的价值在“中断处理期间又按了一次”时才体现：电平会在 EOI 后重投，脉冲会丢。这一点只由单测从寄存器语义上保证，详见 `tests/TEST_DESIGN.md` 的剩余风险。
- **guest 每次启动打印一次 RTC 的 `ACPI Error`。** 这是不实现可选的 `RTC_EN` 的直接结果，pci-bus 和 arch-distro 的日志判据都按预期排除了这一条。
