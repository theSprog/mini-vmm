前面各篇里，guest 内存一直是一块从 GPA 0 开始的连续 RAM，只要不超过 3 GiB 就没出过问题。这一章讲内存一超过 3 GiB 就必须面对的三件事：guest 物理地址空间里除了 RAM 还放着什么；“这里有内存”和“这里的内存能用”为什么是两张不同的表；VMM 拿到一个由 guest 提供的地址时，怎样才能安全地访问它。后面的脏页跟踪、热插拔内存、virtio-mem、迁移都建立在这一章的模型上，到时会回来引用这里。

GVA、GPA、HVA 三层地址和 memslot 的基本概念，《一次 out 指令的完整旅程·原理篇》第七章已经讲过，这里不再重复，只用到其中一个结论：**某段 GPA 是内存还是设备，取决于有没有 memslot 覆盖它。** 有 memslot，guest 的访问由 NPT 直接翻译到 host 内存，不产生陷出；没有 memslot，访问触发 `#NPF`，KVM 把它当成 MMIO 交给设备模型处理。

## 一、guest 物理地址空间里有什么

### 1.1 4 GiB 以下要留一个洞

《固件与启动协议·原理篇》1.2 节画过 PC 的物理地址图：1 MiB 以下是历史遗留的几个区域，3 GiB 到 4 GiB 之间是 MMIO 空洞。前面一直没有处理这个空洞，因为 guest 内存不超过 3 GiB，RAM 根本碰不到那里。

空洞里放的是只能出现在 4 GiB 以下的设备地址：

| 地址 | 内容 | 为什么必须在 4 GiB 以下 |
|---|---|---|
| `0xFEC00000` | IOAPIC 寄存器 | MP table 和 ACPI MADT 里的 IOAPIC 地址字段是 32 位 |
| `0xFEE00000` | LAPIC 寄存器 | CPU 复位后 LAPIC 的默认基址就在这里，Linux 不会去搬动它 |
| 3 GiB 以上的若干段 | 32 位 PCI BAR | 只有 32 位地址能力的 BAR 只能放在 4 GiB 以下 |
| 一段 256 MiB 的窗口 | PCIe ECAM 配置空间 | 以后的 `pcie-ecam` 里程碑会放在这里 |

假设把一台 5 GiB 的 guest 做成一个从 GPA 0 一直铺到 5 GiB 的 memslot，看看 IOAPIC 的一次寄存器写会发生什么：

```
  一个 slot 覆盖 [0, 5 GiB)                     低段 [0, 3 GiB) + 高段 [4 GiB, 6 GiB)

  guest 写 GPA 0xFEC00000                       guest 写 GPA 0xFEC00000
     │                                             │
     ▼                                             ▼
  NPT 里有映射（这是 RAM）                         NPT 里没有映射（没有 slot）
     │                                             │
     ▼                                             ▼
  值写进了 host 的一页匿名内存                       #NPF → KVM 判定为 MMIO
  不产生任何陷出                                    → 内核 MMIO 总线上的 IOAPIC 认领
     │                                             │
     ▼                                             ▼
  IOAPIC 永远收不到这次写，                          重定向表项被更新，
  中断路由配置全部丢失                               中断按 guest 的配置送达
```

左边的问题不会以“报错”的形式出现：guest 照常运行，只是中断不来，症状离原因很远。所以 RAM 必须在 4 GiB 以下让出一个洞，原本应该落在洞里的那部分 RAM 挪到 4 GiB 以上。真实主板的芯片组也是这么做的，叫做内存重映射（memory remapping）。

mini-vmm 的布局是：

```
   GPA
   0x0_0000_0000 ┌──────────────┐
                 │   低段 RAM    │  slot 0，大小 = min(ram_size, 3 GiB)
   0x0_C000_0000 ├──────────────┤  ← 3 GiB，VMM_MEM_HOLE_START
                 │  MMIO 空洞    │  没有 slot
   0x0_FEC0_0000 │   IOAPIC     │
   0x0_FEE0_0000 │   LAPIC      │
   0x1_0000_0000 ├──────────────┤  ← 4 GiB，VMM_MEM_HIGH_START
                 │   高段 RAM    │  slot 1，大小 = ram_size - 3 GiB
                 └──────────────┘  只在 ram_size > 3 GiB 时存在
```

空洞留 1 GiB 而不是只留 IOAPIC 和 LAPIC 那几页，是为了给以后的 PCI BAR 和 256 MiB 的 ECAM 窗口都留出余量。

### 1.2 memslot 和 E820 是两张表

guest 内核要知道哪些物理地址可以拿来分配，这件事由 E820 内存图告诉它（《固件与启动协议·原理篇》1.2 节）。于是同一段 GPA 有两个独立的属性：

- **memslot**：这段 GPA 背后有没有真实的 host 内存。这是 VMM 告诉 KVM 的。
- **E820**：guest 内核能不能把这段内存交给伙伴系统去分配。这是 VMM 告诉 guest 的。

两者可以不一致，而且有些地方必须不一致。拿 5 GiB guest 的几段地址对照：

| GPA 区间 | memslot | E820 | 为什么 |
|---|---|---|---|
| `[0, 0x9FC00)` | 有 | RAM | 普通低端内存，AP 的 trampoline 要用 |
| `[0x9FC00, 0x100000)` | 有 | 保留 | MP table 和 ACPI 表写在这里。表必须写在真实内存里，guest 才读得到，所以要有 memslot；又不能让内核把它分配出去覆盖掉，所以 E820 报保留 |
| `[0x100000, 3 GiB)` | 有 | RAM | 内核、initrd 和运行时内存 |
| `[3 GiB, 4 GiB)` | 无 | **无条目** | MMIO 空洞，见下文 |
| `[4 GiB, 6 GiB)` | 有 | RAM | 高段内存 |

反过来的组合是绝对不允许的：E820 报 RAM 的地方没有 memslot。guest 内核会把那里当成普通内存去分配，而对它的每一次访问都会变成一次没有设备认领的 MMIO：陷出到 VMM，读出全 1，写入被丢弃。内核拿到的是一页存不住任何数据的“内存”。为了从构造上排除这种情况，mini-vmm 的 E820 不是单独写的，而是遍历 RAM memslot 生成的（3.2 节）。

最容易想错的是空洞那一行。直觉上把 `[3 GiB, 4 GiB)` 标成“保留”更完整，但这样做反而有害。Linux 启动时用 `e820__setup_pci_gap()` 给 PCI 子系统找一段地址，用来分配那些固件没有分配地址的 BAR：

```c
/* arch/x86/kernel/e820.c */
#define MAX_GAP_END 0x100000000ull

static int __init e820_search_gap(unsigned long *gapstart, unsigned long *gapsize)
{
	unsigned long long last = MAX_GAP_END;
	int i = e820_table->nr_entries;
	...
	while (--i >= 0) {
		unsigned long long start = e820_table->entries[i].addr;
		unsigned long long end = start + e820_table->entries[i].size;

		if (last > end) {
			unsigned long gap = last - end;
			if (gap >= *gapsize) {
				*gapsize = gap;
				*gapstart = end;
				found = 1;
			}
		}
		...
```

它从 4 GiB 往下，找 E820 条目之间**没有任何条目**的最大空隙。把空洞标成保留，这段空隙就不存在了，内核会打印 `Cannot find an available gap in the 32-bit address range`。不写条目时，dmesg 里是：

```
[mem 0xc0000000-0xffffffff] available for PCI devices
```

这一行就是 `pci-bus` 里程碑以后分配 BAR 的地址池。

## 二、guest 给的地址是信任边界

### 2.1 VMM 什么时候要访问 guest 内存

到目前为止，VMM 访问 guest 内存只发生在启动阶段：写内核镜像、initrd、boot_params、ACPI 表。这些地址都是 VMM 自己选的，不会出错。

从下一组里程碑开始，情况变了。e1000 的收发描述符环、AHCI 的命令表和 PRDT、virtqueue 的每一个 descriptor，里面都是 **guest 自己填的 GPA 和长度**，VMM 要按这些地址去读写数据。guest 可能有 bug，也可能是恶意的，它填的值要多离谱都可以。VMM 是 host 上的一个普通进程，guest 的内存只是它地址空间里 mmap 出来的一段：

```
  VMM 进程的地址空间
  ┌─────────────────────────────────────────────────────┐
  │ 代码  堆  栈  ...  [ guest RAM 的 mmap 区 ]  ...    │
  └─────────────────────────────────────────────────────┘
                       ↑ hva = base + gpa
```

如果 VMM 不经检查就算 `base + gpa`，guest 只要填一个超出 RAM 的地址，就能让 VMM 读写 mmap 区以外的东西：堆上的设备状态、其他 guest 的内存（如果一个进程跑多台），甚至代码。这就是虚拟机逃逸最常见的入口之一。

### 2.2 一个地址范围要检查什么

guest 给的是一个范围 `[gpa, gpa + len)`。只检查起点在 RAM 里是不够的，看几个例子（5 GiB guest，低段 `[0, 0xC0000000)`，高段 `[0x100000000, 0x180000000)`）：

| guest 给的范围 | 只查起点 | 实际问题 |
|---|---|---|
| `gpa=0xFFFFFFFFFFFFFF00, len=0x200` | 不在 RAM 里，拒绝 | 这个例子碰巧被拒，但如果先算 `end = gpa + len` 再比较，`end` 回绕成 `0x100`，`end <= slot_end` 成立，上界检查被绕过 |
| `gpa=0xBFFFF000, len=0x2000` | 在低段里，通过 | 后 4 KiB 落进空洞。HVA 上低段后面紧挨着就是高段（3.1 节），于是 VMM 会把本该进空洞的数据写进 GPA 4 GiB 处的内存 |
| `gpa=0x17FFFF000, len=0x2000` | 在高段里，通过 | 后 4 KiB 超出了 RAM 末尾，越过整个 mmap 区 |
| `gpa=0x1000, len=0` | 在低段里，通过 | 长度为 0 的描述符往往说明 guest 驱动或 VMM 的解析逻辑有 bug，应该被看见而不是被默默接受 |

所以一个合格的检查必须：

1. 先检查 `gpa + len` 是否超出 2^64，再做任何范围比较；
2. 要求整个范围落在**同一个** memslot 里，而不是只看起点；
3. 拒绝零长度。

第 2 条里的“同一个”很关键。两个 slot 在 GPA 上相邻，不代表它们在 HVA 上相邻；即使 HVA 恰好相邻（mini-vmm 的低段和高段就是），GPA 上中间也可能隔着空洞。跨 slot 的访问要由调用方拆成几段，每段单独检查。以后 virtqueue 的 descriptor chain、AHCI 的 PRDT 都是这样：链上每一段单独过一遍检查。

### 2.3 拒绝要说清原因

检查失败时，“失败”这个信息本身不够用。下面两种失败指向完全不同的 bug：

- 起点不在任何 slot 里：通常是 `--mem` 给小了，或者 guest 填了垃圾地址；
- 起点在 slot 里，但范围跨进了下一个 slot：说明调用方本该拆分却没拆，是 VMM 的 bug。

如果转换函数只返回一个指针、失败时返回 `NULL`，调用方只能打出 `out of bounds`，读日志的人还得自己算一遍地址才知道是哪一种。mini-vmm 的做法是让转换函数返回一个状态码，HVA 从出参给出：

```
  返回指针的接口                              返回状态的接口

  void *p = gpa_to_hva(vm, gpa, len);         void *p;
  if (!p)                                     st = gpa_to_hva(vm, gpa, len, &p);
      err("GPA [%lx,+%lx) out of bounds");    if (st != GPA_OK)
                                                  err("GPA [%lx,+%lx): %s", gpa_status_str(st));

  日志：GPA [0xbffff000,+0x2000)              日志：GPA [0xbffff000,+0x2000):
        out of bounds                               range runs past the end of its memslot
```

## 三、mini-vmm 的实现

### 3.1 一次 mmap，两个 memslot

```c
/* src/mem.c: mem_init() */
    ram_size = ALIGN_UP(ram_size, PAGE_SIZE);
    low  = ram_size < VMM_MEM_HOLE_START ? ram_size : VMM_MEM_HOLE_START;
    high = ram_size - low;

    p = mmap(NULL, ram_size, PROT_READ | PROT_WRITE,
             MAP_PRIVATE | MAP_ANONYMOUS | MAP_NORESERVE, -1, 0);
    ...
    r = add_ram(vm, 0, low, p);
    ...
    if (high) {
        r = add_ram(vm, VMM_MEM_HIGH_START, high, p + low);
        if (r != VMM_OK) {
            munmap(p + low, high);
            mem_destroy(vm);
            return r;
        }
    }
```

guest 内存只 mmap 一次，低段从 HVA `p` 开始注册成 GPA 0，高段从 HVA `p + low` 开始注册成 GPA 4 GiB。两个起点都是 1 GiB 对齐，透明大页在两段上都能用。`MAP_NORESERVE` 让 5 GiB 的 guest 启动时不需要 host 真有 5 GiB 空闲：物理页在 guest 第一次访问时才由 host 缺页分配。

高段注册失败时，已经注册的低段通过 `mem_destroy()` 撤销，不会留下只有一半的内存布局。

每个 slot 带一个 `ram` 标记。现在只有 `mem_init()` 注册的 slot 是 RAM；以后 VFIO 把设备 BAR 映射进 guest 也要注册 memslot，但那不是 RAM，不能写进 E820。

### 3.2 E820 由 memslot 生成

```c
/* src/boot/zeropage.c */
    for (; s; s = mem_next_ram_slot(vm, s->gpa + s->size)) {
        if (s->gpa == 0) {
            e820_add(bp, 0, ZP_EBDA_START, E820_TYPE_RAM);
            e820_add(bp, ZP_EBDA_START, ZP_HIGH_MEM_START - ZP_EBDA_START,
                     E820_TYPE_RESERVED);
            e820_add(bp, ZP_HIGH_MEM_START, s->size - ZP_HIGH_MEM_START,
                     E820_TYPE_RAM);
        } else {
            e820_add(bp, s->gpa, s->size, E820_TYPE_RAM);
        }
    }
```

`mem_next_ram_slot(vm, gpa)` 返回起点不低于 `gpa` 的 RAM slot 里最低的那个，于是这个循环按 GPA 升序走遍所有 RAM。GPA 0 起的 slot 按 1.2 节的表拆成三项，其他 slot 原样一项，slot 之间的空洞不写任何条目。E820 里的每一个 RAM 字节都来自某个 memslot，1.2 节说的那个“绝对不允许”的组合在构造上就不可能出现。

### 3.3 initrd 仍然放在低段

《固件与启动协议·实现篇》2.3.3 节把 initrd 放在“RAM 顶端向下 2 MiB 对齐”，代码里的“RAM 顶端”就是 `ram_size`。内存只有一段时，`ram_size` 既是 RAM 的大小，也是 RAM 末尾的地址，两种含义恰好重合。有了空洞之后它们分开了：

```
  5 GiB guest
  ram_size              = 0x140000000   大小：5 GiB
  RAM 实际的最高地址       = 0x17FFFFFFF   在高段里
  低段 RAM 的末尾          = 0xC0000000
  [0xC0000000, 0x100000000) 是空洞，0x140000000 在高段中间，都不是“RAM 顶端”
```

initrd 又只能放在 4 GiB 以下：setup header 里的 `initrd_addr_max` 是 32 位字段（`Documentation/arch/x86/boot.rst`），vmlinux 路径用的上限是 `0x37ffffff`。所以 4 GiB 以下能放 initrd 的 RAM 只有低段，`load_initrd()` 取的顶端是 GPA 0 所在 slot 的末尾，再受 `initrd_addr_max` 限制。还按 `ram_size` 算的话，今天的结果碰巧正确，只是因为 `initrd_addr_max` 比 3 GiB 小，把错误的顶端截了下来；它依赖的是一个和内存布局无关的巧合。5 GiB guest 上 initrd 落在 `0x37e00000`，正好是上限以下 2 MiB 对齐的位置。

### 3.4 `gpa_to_hva()`

```c
/* include/memory.h */
enum gpa_status {
    GPA_OK = 0,
    GPA_ERR_ZERO_LEN,       /* len == 0 */
    GPA_ERR_WRAP,           /* 结束地址 gpa + len >= 2^64，64 位表示不了 */
    GPA_ERR_UNMAPPED,       /* gpa 不在任何 slot 里 */
    GPA_ERR_CROSSES_SLOT,   /* 从一个 slot 延伸进紧邻的另一个 slot */
    GPA_ERR_PAST_END,       /* 从 slot 延伸到没有 slot 的地址 */
};

/* src/mem.c */
enum gpa_status gpa_to_hva(struct vmm_vm *vm, uint64_t gpa, uint64_t len,
                           void **hva)
{
    ...
    if (len == 0)
        return GPA_ERR_ZERO_LEN;
    if (gpa + len < gpa)
        return GPA_ERR_WRAP;

    s = mem_find_slot(vm, gpa);
    if (!s)
        return GPA_ERR_UNMAPPED;
    slot_end = s->gpa + s->size;
    if (gpa + len > slot_end)
        return mem_find_slot(vm, slot_end) ? GPA_ERR_CROSSES_SLOT
                                           : GPA_ERR_PAST_END;

    *hva = (uint8_t *)s->hva + (gpa - s->gpa);
    return GPA_OK;
}
```

顺序就是 2.2 节的三条规则：先零长度，再回绕，最后才做范围比较。`gpa + len < gpa` 在无符号运算下正好等价于“回绕了”，它必须排在 `gpa + len > slot_end` 之前，否则回绕后的小数值会通过上界比较。范围超出 slot 末尾时，再看末尾之后紧接着有没有别的 slot，用来区分 `CROSSES_SLOT` 和 `PAST_END`。拒绝时 `*hva` 保持不变，调用方不会拿到一个半对的指针。

2.2 节表里的四个例子在这里分别得到：

| 范围 | 结果 |
|---|---|
| `0xFFFFFFFFFFFFFF00 + 0x200` | `GPA_ERR_WRAP` |
| `0xBFFFF000 + 0x2000` | `GPA_ERR_PAST_END`（低段末尾之后是空洞，没有 slot） |
| `0x17FFFF000 + 0x2000` | `GPA_ERR_PAST_END` |
| `0x1000 + 0` | `GPA_ERR_ZERO_LEN` |

VMM 里所有访问 guest 内存的地方，包括内核装载、boot_params、MP table、ACPI 表、页表，都经过这个函数或建立在它之上的 `mem_read()`/`mem_write()`/`mem_load_file()`。失败时日志里带着原因，比如用 `--mem 1M` 去跑一个装在 `0x300000` 的长模式 payload：

```
[ERR ] failed to load build/serial64.bin: GPA 0x300000 + 168 bytes: start is not in any memslot (try a larger --mem)
```

## 四、证据

### 4.1 一台 5 GiB 的 guest

```bash
./build/vmm --mode linux --mem 5G --initrd build/initramfs.cpio.gz vmlinux
```

VMM 这一侧，两个 memslot 和由它们生成的 E820：

```
[INFO] memslot 0: GPA [0x0, 0xc0000000) -> HVA 0x7b60c4800000 (3072 MiB)
[INFO] memslot 1: GPA [0x100000000, 0x180000000) -> HVA 0x7b6184800000 (2048 MiB)
[INFO]   e820: [0x000000000000, 0x00000009fc00) RAM
[INFO]   e820: [0x00000009fc00, 0x000000100000) reserved
[INFO]   e820: [0x000000100000, 0x0000c0000000) RAM
[INFO]   e820: [0x000100000000, 0x000180000000) RAM
[INFO] initrd @ GPA 0x37e00000, 770316 bytes
```

两个 slot 的 HVA 相差 `0xC0000000`，正好是低段的长度：它们来自同一次 mmap。

guest 内核这一侧，先是原样收下这张表，再把空洞交给 PCI：

```
BIOS-e820: [mem 0x0000000000000000-0x000000000009fbff] usable
BIOS-e820: [mem 0x000000000009fc00-0x00000000000fffff] reserved
BIOS-e820: [mem 0x0000000000100000-0x00000000bfffffff] usable
BIOS-e820: [mem 0x0000000100000000-0x000000017fffffff] usable
RAMDISK: [mem 0x37e00000-0x37ebcfff]
NODE_DATA(0) allocated [mem 0x17ffc1000-0x17fffffff]
  DMA32    [mem 0x0000000001000000-0x00000000ffffffff]
  Normal   [mem 0x0000000100000000-0x000000017fffffff]
[mem 0xc0000000-0xffffffff] available for PCI devices
```

`NODE_DATA(0)` 这一行值得注意：memblock 分配器自顶向下分配，内核最早的几次分配就落在高段的末尾 `0x17ffc1000`。也就是说，高段 RAM 在内核启动的最初阶段就已经被读写了，如果高段的 memslot 有问题，内核根本走不到后面。

guest 起来之后，在 shell 里看伙伴系统：

```
[guest ~]# grep -A12 "zone   Normal" /proc/zoneinfo | grep -E "spanned|present|managed"
        spanned  524288
        present  524288
        managed  499889
[guest ~]# grep start_pfn /proc/zoneinfo
  start_pfn:           1
  start_pfn:           4096
  start_pfn:           1048576
[guest ~]# grep MemTotal /proc/meminfo
MemTotal:        5003500 kB
```

三个 zone 的起始页帧号依次是 DMA、DMA32、Normal。Normal 从页帧 1048576 开始，乘以 4 KiB 正好是 4 GiB；它有 524288 页，正好是高段的 2 GiB。`MemTotal` 比 5 GiB 少两百多 MiB，少掉的是内核镜像、页表和其他启动时预留的内存，以及 E820 里那段保留区。

### 4.2 自动化测试

`make test guest-memory` 跑 `tests/e2e/guest-memory.sh`，判据分三层，每一层只靠上一层不足以证明：

| 层 | 判据 | 证明了什么 |
|---|---|---|
| VMM 日志 | 两条 `memslot` 行和对应的 `e820:` 行 | VMM 按设计切分了内存，并且 E820 与之一致 |
| guest dmesg | `BIOS-e820` 原样出现；`available for PCI devices` 从 `0xc0000000` 开始 | 内核收下了这张表，空洞没有被标成保留 |
| guest 运行时 | Normal zone 的 `start_pfn` 是 1048576、`present` 是 524288，`MemTotal` 超过 4 GiB | 高段内存真的进了伙伴系统，而不只是出现在表里 |

如果 VMM 不在 4 GiB 以下留洞，它只能拒绝超过 3 GiB 的内存，guest 起不来，这个测试的每一条都会失败。

`gpa_to_hva()` 本身的边界由单元测试覆盖。`tests/unit/mem_test.c` 对 2.2 节的每一种情况都有用例，并且用 9 个故意写错的变体（比如漏掉回绕检查、只按起点查 slot、把相邻 slot 当成连续内存）证明这些用例真的能发现错误：每个变体都必须让至少一个用例失败。`tests/unit/boot_tables_test.c` 用真实的 `src/mem.c` 和 `src/boot/zeropage.c` 构造 5 GiB 的布局，逐项核对 E820 条目和 RAM slot 一一对应。
